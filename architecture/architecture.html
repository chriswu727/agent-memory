01 · Goals and boundaries

The goal is a headless autonomous memory runtime. Once an agent is integrated, memory automatically participates in understanding, reasoning, responses, and learning on every turn. The system must form, use, and update memories even when users issue no memory commands, the primary agent never calls memory tools, and no management page exists. Completeness is judged by the cognitive cycle, data invariants, integration semantics, and operational acceptance.

In this specification, “brain-inspired” means borrowing the functional division of cognitive mechanisms. The system does not claim to reproduce a biological brain, create consciousness, or change base model weights through an external database alone. Fast episode encoding and slower consolidation of regularities draw on complementary learning systems; integration within a bounded workspace draws on working-memory research. All concrete algorithms remain engineering implementations that require evaluation.

The compatibility target is a memory protocol independent of models and frameworks, supporting text context injection, tool calls, application lifecycle hooks, and standard APIs. Automatic capture of complete experiences, workspace updates, and control over compaction depend on the capabilities a host actually exposes. Closed applications with no integration interface are outside the promise of direct integration.

Complete records can live externally, and each turn can have a workspace budget. Perfect answers to arbitrary historical questions, fixed read cost, and fixed latency cannot all be guaranteed. Complex retrospection may use multiple retrievals within a budget and must report its coverage.

This directory specifies the complete product target. Implementation of the runtime, clients, and local workbench has begun; see the engineering documentation for actual capabilities and validation boundaries. Machine-readable interface objects are in memory-contract.schema.json, and behavioral acceptance is in acceptance-scenarios.json. These files describe the complete intended behavior; they do not mean every target is implemented or every acceptance check has passed.

02 · Invariants that must always hold

  1. Keep original experiences separate from derived understanding. Summaries, vectors, and associations are rebuildable; normal consolidation must not rewrite the original expression.
  2. Historical assertions must be traceable to sources. A source proves that an expression occurred, not automatically that its claims about the world are true.
  3. Manage storage retention, current activation, evidence state, and applicability separately. Repeated retrieval or restatement does not increase truthfulness.
  4. Propagate corrections to dependent summaries, associations, working states, and caches. Both historical and current states remain queryable.
  5. Distinguish users, agents, relationships, channels, and conversation branches explicitly. Apply authorization filters before candidate content enters a model.
  6. Memory is reference material. Historical text cannot become system instructions, expand tool permissions, or authorize future actions.
  7. Acknowledged events must be recoverable after persistence; background failures must be retryable; repeated submission of the same event must not create duplicate experiences.
  8. New records not yet indexed must have a supplemental read path. Report service failure, indexing backlog, and no retrieval match separately.
  9. Deletion blocks future recall and propagates to derivatives. Restoring a backup must not re-expose deleted content.
  10. Migration between models preserves sources and semantic versions. Validate style, reasoning ability, and memory use separately.
  11. Measure current context, additional retrieval, background organization, storage, and backups separately. Record all model calls in one cost ledger.
  12. Never present missing capabilities as success. Each adapter declares, validates, and exposes the lifecycle operations it can perform.

03 · The complete cognitive cycle

Current input and situation→Cue activation→Bounded workspace→Response and action→Actual outcome→Episode encoding→Consolidation and activation updates

The next input uses the updated episodes and beliefs. The core manages memory state and reads and writes; the host model remains responsible for immediate language understanding, reasoning, and expression. Software enforces permissions, budgets, versions, and provenance constraints, while models propose semantic interpretations and organizational candidates.

ModuleResponsibilityRequired boundaries
Situation understanding and working memoryCurrent goals, person references, temporary needs, unanswered questions, and interruption pointsMaintained per branch; bounded capacity; inferred conversational needs can be corrected immediately
Episodic memoryWhat happened in an experience: antecedents, sequence, original wording, and outcomePreserve event boundaries and sources; distinguish plans from completed events
Semantic memoryPreferences, relationships, knowledge, and regularities learned from experienceInclude valid time, applicability, supporting evidence, and contrary evidence
Procedural memoryHow to handle a task and when a method worksSuccess needs outcome evidence; environmental changes may invalidate a method; no execution authority is granted

Agent identity, core behavioral constraints, and authorization belong to separate versioned configuration. Experiences may support communication preferences, but consolidation jobs cannot modify identity or permissions on their own. Label real experiences, roleplay, and simulated environments separately.

Context compaction organizes the current workspace, retaining goals, unfinished matters, the latest state, and necessary source pointers. Long-term memory is continually reconstructed from original events and versioned beliefs, not solely from repeatedly compressed summaries. Hosts with compaction hooks use checkpoint handoffs; other hosts keep their own compaction and recover relevant memory through the next prepare operation.

An example spanning the system

Suppose a user preparing for an exam says, “For now, chat with me for ten minutes in the evening before helping me plan my revision.” The current workspace adopts this request immediately; episodic memory preserves the wording and situation; semantic memory forms a preference conditional on exam preparation; prospective memory retains the revision planning not yet started in this turn. These are distinct objects and must not collapse into “the user dislikes planning.”

Weeks later, the user says, “It is another evening when I cannot focus on studying.” The system retrieves relevant experiences from the current situation and implicit cues and adjusts its communication. It need not recite old records, and must not infer a permanent emotional state. After the exam, the user explicitly says, “From now on, just help me plan directly.” The new preference takes effect immediately; the old one remains as historical state.

Months later, ordinary conversation no longer carries this experience. If the user asks, “What did we agree on during exam preparation?”, the system locates the old experience through time, goals, and relationships, then expands the retained wording as needed. If the wording is unavailable, it can report only a generalization still supported by legitimate evidence and what is missing; it cannot invent details such as ten minutes. Generalizations covered by deletion must also leave recall. Acceptance checks each change above, rather than merely checking that a database record exists.

04 · Data objects and orthogonal states

Core objects include original Event, Episode, Assertion, Association, Procedure, future Intention, WorkingState, and RecallTrace. Versions and dependencies express changes to these objects; query views are rebuildable.

Common memory envelope
  Identity: tenant / brain / participant / relationship / conversation / branch
  Scope: readable scope, disclosure scope, situation, real or simulated world
  Provenance: event IDs, source spans, derivation dependencies, extractor version
  Time: event time (possibly unknown or an interval), learned time, validity bounds
  Nature: statement, observation, inference, hypothesis, quotation, roleplay
  State: currently valid, historically valid, contested, corrected, deleted
  Retention: long-term value, detail policy, explicit pinning, user retention policy
  Representation: semantic anchors, outlines, specific fragments, and original sources of one episode
  Accessibility: independent everyday-candidate, cue-expansion, or deep-lookup state per representation
  Activation: external use history, recency, current cue match
  Version: revision, supersession, authorization and deletion generations

“Direct statement” is a source type; it does not mean a world fact was independently verified. An explicitly stated user preference can directly support the current preference; one inferred from repeated behavior retains its inferred status. Multiple summaries of one source are not independent evidence.

Association edges have types such as participation, location, sequence, support, contradiction, supersession, and co-occurrence. Temporal proximity or semantic similarity cannot automatically become causality. People sharing a name retain separate identities; merges require evidence and must be reversible.

Every derived assertion retains a specific support path. Its disclosure scope must not exceed the scope jointly permitted by sources along that path. Sufficient independent public evidence may support a separate shared projection; consolidating private wording alongside public material must not leak private details into a shared summary. Recheck support paths after source deletion or permission changes.

Emotional information distinguishes explicit user expression from model inference and may serve as a cue to the situation at the time. It does not automatically become a lasting personality label or gain disclosure priority. Relationship memory records communication habits, agreements, and shared experiences, rather than replacing relationship state with a single “affinity” score.

05 · Fast encoding and slow consolidation

Reliable write path

  1. Check scope, event type, message ID, and content integrity using the host-authenticated identity.
  2. Save the actual event and pending jobs in one transaction, then acknowledge persistence. The same idempotency key and content can be retried safely; different content returns a conflict.
  3. Record the server sequence and source time. Newly stored original text is immediately available for supplemental workspace reads.
  4. Distinguish drafts, cancelled output, generated but undelivered responses, and delivered responses. They cannot all count as conversation the user experienced.

Understanding and consolidation path

  1. Form episodes around topics, goals, participants, and event boundaries. Segments may overlap and boundaries may be revised.
  2. Extract entities, time, candidate assertions, unfinished matters, and associations with source locations.
  3. Check structure, source existence, authorization, duplicates, temporal conflicts, and semantic support. Programmatic validation proves source existence; semantic support still requires model assessment and quality sampling.
  4. Publish versioned event cards, assertions, associations, and indexes; update processing progress.
  5. Generalize new or affected experiences while retaining exceptions and contrary evidence. Procedural memory requires actual task outcome support.
  6. Corrections, deletions, or new counterexamples invalidate dependencies and trigger local rebuilding, followed by an atomic switch of the valid view.

New evidence, conflicts, task completion, or backlog trigger background consolidation; it does not depend on summarizing all history daily. Repeated reflection without new evidence cannot increase factual confidence. Repeated use supported by independent sources may strengthen evidence for a method's applicability, but the model's own restatements cannot accumulate without limit.

The fast path prevents loss after something happens; the slow path determines how experience becomes understanding. Indexing delay between them must be visible and bridged by supplemental reads of newly stored source text.

The transaction accepting a correction records the new evidence, advances the dependency generation, and invalidates affected old projections without waiting for background regeneration. During rebuilding, reads return confirmed corrections, valid original text, and partial-coverage state. Working states and caches must also check invalid dependencies. Historical queries remain allowed, but old relationships must not be presented as current facts.

06 · Situation-driven recall and workspace composition

  1. Understand the need. Use the new message and working state to determine whether the turn needs exact wording, current facts, an episode, a history of change, a method, or a future matter. Preserve multiple reference candidates.
  2. Constrain scope. Filter eligible material by subject, relationship, channel, time, and authorization before retrieval. The server does not trust arbitrary user identities supplied by a model.
  3. Retrieve through multiple paths. Combine keywords, semantics, entities, time, relevant unfinished matters, and the recent tail. Chinese retrieval requires Chinese tokenization or character-based search, not unmodified English tokenization defaults.
  4. Expand bounded associations. Traverse typed associations with limits on depth, candidates, reads, and time. Reduce the influence of generic highly connected nodes such as “user” or “work.”
  5. Verify and expand. Deduplicate, check current versions and validity, and retrieve surrounding messages, cancellations, counterexamples, and corrections. Read cards before expanding the required source text.
  6. Allocate the workspace. Allocate tokens by relevance, evidence, coverage, and redundancy, preserving necessary time and uncertainty markers. Ten duplicate plans must not crowd out one cancellation.
  7. Assess sufficiency. The metamemory controller decides whether to search further, answer the known part, state limitations, or request a discriminating cue.

The initial implementation may use rank fusion across retrieval paths and an interpretable selection policy, rather than treating raw scores from different retrievers as one scale. Return similarity, recall ranking, and evidence reliability separately. Approximate vector indexes require separate candidate-recall measurement and exact retrieval or source lookup for important scenarios.

The workspace should contain enough to support understanding of this turn: stable constraints, current state, necessary recent conversation, relevant evidence, unknowns, and conflicts. It does not store hidden chain-of-thought or require all personality information, pinned memories, and history in context simultaneously.

After memory enters the model, distinguish direct citation, background influence, and non-use this turn. Remembering that the user prefers relaxed conversation when stressed can shape a response without repeatedly recounting an old experience. Historical-claim checks should prioritize concrete claims such as “you always,” “last time we,” and “already completed.” Their effectiveness must be measured; they are not an absolute hallucination guarantee.

07 · Forgetting, reactivation, and reconsolidation

Multiple representations and independent decay within one episode

The following are architectural targets not yet implemented. Encoding organizes an experience into linked, meaning-preserving fragments, each with representations at different granularities. Granularity and accessibility are independent: an important concrete scene can remain easy to recall for years, while an outdated generalization can fade. Levels evolve with time and new experiences; an entire history is not permanently assigned one importance level.

RepresentationPrimary-school examplePreserved content
Semantic anchorAttending a particular school and the teacher at the timeEntities and relations, time range, negation, provenance, and expression type
Episode outlineA school transfer during primary schoolPeople, main events, changes, and outcomes, including unknowns and exceptions
Specific fragmentAn event on the playground on graduation daySource-supported scenes and details; important fragments can be retained independently
Original sourceThe wording used to describe these experiencesSource text and locations retained under policy; not loaded wholesale into the workspace by default

Keywords can provide lasting index entries, but cannot carry facts alone. For example, “I never attended Xinghe Primary School; I only went there for a competition” must not reduce to “me—Xinghe Primary School” and imply attendance. Roles, relations, negation, validity, conditions, and the distinction between reality and imagination must remain in the minimum semantic unit. Expand details only when their sources are available.

Cross-episode generalizations become separate versioned assertions; not every message needs one. Repeatedly useful, supported beliefs may decay more slowly, but greater generality does not automatically mean greater truth or permanent relevance. New counterexamples may change applicability and current validity while old experiences retain their original meaning.

Each fragment and representation independently tracks retention value, activation, detail availability, and evidence state. Accessibility has everyday-candidate, cue-expansion, and deep-lookup tiers; easy retrieval does not mean permanent context residency. Defaults favor faster fading of ordinary details and slower fading of stable anchors, with exceptions for user-designated importance, unfinished commitments, and useful fragments. User importance signals, external outcomes, and new evidence may update policy; repeated model retrieval or restatement must not inflate importance or truthfulness.

Queries first find a small number of anchors and outlines, then expand as needed through entities, time, people, and event links. Explicit cues can also search deep fragments directly so details omitted from higher-level summaries do not become permanently unreachable. Reactivation promotes only the fragments needed now, not an entire primary-school history. Search depth, read volume, and model calls remain budgeted.

Continuous stratification uses timestamp-based lazy decay and local organization triggered by new evidence, actual use, corrections, or policy changes. Background work processes only due or affected objects; it does not rescan and resummarize all history each turn. Demotion without semantic change can use deterministic policies without model calls. Long-term evaluation must establish decay parameters and tier capacity, rather than assuming one duration for every memory.

Record demotion, removal from expensive indexes, and actual content erasure separately. Removing only a derived index still permits authorized source lookup. If a detail is truly erased, related summaries, keywords, vectors, and caches must not continue leaking it. Remaining content is usable only when retained legitimate sources sufficiently support it; a hash or invalid pointer is not evidence. This target does not enable automatic erasure of existing data.

Stratification acceptance includes retaining a school name and a few important fragments after years; retrieving faded ordinary details through valid cues; preserving important fragments independently of surrounding content's age; retaining negation and conditions through compaction; promptly updating generalizations after counterexamples; and preventing upper-level representations from reproducing erased details. Tests may simulate time; real-model quality and scale effects require separate evaluation.

Fading

Lower default activation and everyday workspace priority while retaining original evidence. Explicit cues, current goals, or unfinished matters can reactivate it.

Detail reduction

Keep episode outlines and association entry points while reducing expensive derived representations. A separate policy governs source retention; only supported details can be recovered.

Deletion

Remove content and derivatives under a user request or retention policy and block subsequent recall. “Simulated forgetting” must not obscure deletion state.

Reinterpretation

When new information changes an old experience's meaning, publish a new interpretation version while preserving evidence of what happened and why the interpretation changed.

Activation policy separately considers external use history, recency, cue match, current goals, distinctiveness, and user-designated importance. Original retention value and evidence state do not automatically increase on retrieval. Real tasks calibrate time-decay parameters; there is no claim of one universal “human forgetting formula.”

Persistent archives follow the user's selected retention policy. Default cognitive fading does not delete original records; only explicit retention periods, detail-erasure settings, or deletion requests trigger content cleanup. Long-term preservation requires verifiable backups, recovery, and migration, rather than reliance on one service process or database copy.

Different details within an episode may follow different retention policies. An ordinary conversation may gradually retain only a generalization, while one phrase that later becomes a shared nickname remains. An old unfinished commitment does not expire merely because it is rarely mentioned.

Prompts are query cues only. “Do you remember when we went to the beach?” does not itself prove an old experience exists. The system must recover details from existing sources or clearly record newly supplied information as a current statement. Tests must count genuinely recovered additional details, not repetition of the user's cue.

Historical recall freezes the retrieval snapshot and evidence cutoff. Server observation order defines experiences recorded before the question; a past date mentioned in a cue cannot replace that boundary. The current cue and its derivatives can rewrite queries but cannot independently prove an old memory. Presuppositions in questions are not extracted as completed events by default, and repeated questioning is not independent evidence. Different cue-strength experiments start from the same historical snapshot.

Human recall can contain errors and interference. The product need not deliberately imitate those defects. The useful targets are bounded attention, cue dependence, gradual generalization, and revisable understanding.

In addition to state, return searched time and scope, uncovered areas, indexing watermarks, authorization and deletion generations, source versions, budget use, and candidate competition. The primary state must not hide coexisting degradation factors.

The core provides observable evidence. Any probabilistic confidence output must be calibrated on held-out data with error reporting. Without calibration, return evidence states and ranking scores, not misleadingly precise percentages.

Recall feedback distinguishes candidate hits, workspace inclusion, direct citation, estimated background influence, user re-mention, explicit confirmation, correction, and observable task outcomes. Model self-assessment is not external confirmation. Record retrieval access separately from actual use; background self-retrieval does not strengthen evidence or extend retention. The controller records reasons for further searching, new evidence, and stopping; policy calibration uses independent evaluation.

09 · Runtime architecture

The architecture uses a modular service, separate background workers, and one authoritative store. It can run on one machine or scale horizontally. Cognitive modules collaborate through stable internal interfaces; every cognitive concept need not become a microservice.

Application plugin / Host SDK / API adapter / MCP client / Management UI
                            ↓
                Authentication, capability negotiation, memory application service
                            ↓
     Identity and scope · Events and versions · Working state · Recall control · Lifecycle
                  ↙                         ↘
   PostgreSQL + pgvector + Chinese keyword index       Consolidation worker
   Events / Assertions / Relations / Permissions / Jobs / Versions     Extraction / Association / Consolidation / Rebuilding
                  ↓                         ↓
         Object storage or local attachments           Replaceable model and embedding providers

PostgreSQL stores events, assertions, entities, relation edges, versions, authorization, processing progress, and jobs. Vectors use pgvector; graph traversal uses budgeted relational queries. Attachments use object storage, or a local filesystem for self-hosting. Indexes, cards, and summaries are projections, not independent authorities on factual truth.

Python suits the cognitive core, model interfaces, and evaluation. HTTP uses typed requests and generated OpenAPI; a separate MCP adapter exposes the same application service. The management UI and TypeScript SDK consume the same contract. Pin dependency versions and run compatibility checks during implementation; this specification does not replace SDK documentation.

Event writes and outbox jobs commit in the same transaction. Workers use leased claims, at-least-once processing, and idempotent publication. External model calls do not hold long database transactions. Recheck sources, revisions, and deletion generations before publishing; discard or reprocess invalid results.

Caches are optional and cannot be the sole state authority. Cache keys include identity scope, authorization version, memory version, retrieval configuration, embedding version, and necessary context fingerprints. Corrections and deletions invalidate affected caches; process restarts do not compromise record integrity.

Do not maintain separate authoritative facts in relational, vector, and graph databases. Add specialized retrieval services only when measured scale or retrieval needs justify them, using rebuildable projections while preserving the authoritative store and version interfaces.

10 · Time, concurrent conversations, and branches

Each turn reads an explicit snapshot; working-state commits check the expected revision. Conversations maintain separate working states. Shared long-term assertions reconcile through provenance and valid time, rather than simple last-write-wins.

Event time and learned time are separate. A user describing last year's experience today must not overwrite today's state. Reposition late messages using source order and time. If a natural-language date cannot be resolved uniquely, preserve an interval or unknown rather than inventing precision.

Conversation branches retain common ancestry and branch identity. Experimental branches, simulated actions, and actual execution results remain separate. Branch merging explicitly identifies accepted events; mutually exclusive hypotheses cannot both become real experiences. Retries and edits do not mean the same event happened again.

Corrections or deletions between prepare and commit invalidate context through memory generations. Full adapters check before sending and recompute or abort. Tool-only hosts may not be able to interrupt generation already in progress and must expose that limitation in capability declarations.

During indexing backlog, prepare supplements reads with the committed but unindexed tail. If that tail also exceeds budget, return coverage limits and backlog state. Do not concatenate without bound or treat unseen content as nonexistent.

11 · Universal integration contract

A host adapter bound at initialization integrates the product with an agent, automatically receiving message, inference, and delivery lifecycle events and managing memory context. The adapter invokes the operations below; business code and the primary agent do not manually orchestrate each turn. The cognitive controller must trigger necessary recall itself; primary-agent tool use is supplementary. The full responsibilities are defined in the autonomous memory runtime contract, which remains an implementation target.

Full SDK integration includes real event capture, prepare before responses, recall when needed, commit of actual outcomes, and supported checkpoints. API proxies must receive stable identity, conversation, branch, and request identifiers; replacing a URL alone does not create these semantics. Text-only models can use memory through host-injected ContextPacket data, but the host owns the active recall cycle.

Capability negotiation covers at least automatic capture, pre-response injection, tool calling, actual delivery confirmation, branches and edits, compaction handoff, cancellation, stable principal identifiers, tokenizer support, streaming, and multimodal input. Adapters run the same contract tests before release.

MCP exposes active recall and memory operations. MCP itself does not dictate host context management or automatically read complete conversations. Capability and diagnostic interfaces must report verified lifecycle coverage; being connected does not imply full automation. Merely appending retrieved text to a model request does not satisfy complete memory-context management.

12 · Identity, isolation, and data lifecycle

Brain identity is separate from model names. Tenants own brains; roles and participants have distinct identities within a brain. Model relationship memory and channel visibility explicitly. Cross-application identity binding requires verification; matching names, nicknames, or expressions do not justify automatic merging.

The authenticated principal determines available scope. Model-supplied brain or participant parameters can narrow scope but cannot expand authorization. Candidate retrieval, source reads, attachments, exports, asynchronous jobs, and caches all enforce scope. PostgreSQL RLS provides additional isolation; application roles must not be superusers or have BYPASSRLS.

Read permission and disclosure scope are separate. A private-chat source visible to its owner must not automatically enter a group-chat context. Authorize shared knowledge, agent configuration, and shared experiences separately.

Deletion first revokes recall eligibility and advances the deletion generation transactionally, then clears source text, vectors, summaries, relations, working-state references, caches, and background jobs. Audit keeps only necessary content-free operation records. Event sourcing is not a reason to refuse user deletion.

Backups have explicit erasure windows. A restored environment applies an independently maintained deletion manifest before reopening reads. Imports do not restore old authorization or service keys. Report whether already-generating contexts can be withdrawn according to adapter capabilities; do not promise unenforceable immediate deletion.

Migration packages contain versioned objects, sources, states, and associations, optionally including attachments. Vectors are rebuildable and regenerated when model or embedding services change; do not mix incompatible embedding spaces. Test memory use and communication style separately after changing models.

13 · Headless product and essential developer observability

The deliverable is an embeddable or independently deployed memory runtime with host adapters. Brain identity, scope, processing models, and budgets are configured at binding; the runtime handles per-turn memory behavior. Management pages, timelines, and visual graphs are not required. The existing workbench is removable development assistance.

Status interfaces report readiness, lifecycle coverage, persistence and indexing watermarks, consolidation backlog, and failures. Metrics separately measure foreground and background context, calls, costs, and latency. Structured logs connect the turn's input, recall, context selection, commit, and background updates through trace_id and turn_id.

Each decision records relevant event and memory versions, policies and processors, selection or stopping reasons, budget use, and outcomes. Developers can trace why a memory was recalled, why searching stopped, and which new evidence changed a belief. Diagnostics use observable events and policy outputs, without requesting or storing hidden model reasoning.

Logs do not copy conversation text by default. Source expansion rechecks identity and scope and follows deletion constraints. Internal audit and development logs must not become the agent's episodic memory. An existing dashboard and partial recall traces do not mean complete observability interfaces are implemented.

Local storage and local model processing are independent settings. Configuration and capability interfaces explicitly describe remote-processing data flows. Hosted, self-hosted, and local deployment share core capabilities and migration formats. Developer observability must not become a manual prerequisite for ordinary conversation or memory operation.

14 · Cost, capacity, and operational quality

Each request accepts budgets for tokens, model calls, candidate reads, and deadlines. Workspace allocation must subtract system rules, tool schemas, current input, and output reserves. Without a tokenizer, report an estimate rather than treating character count as exact tokens.

The total cost ledger includes episode extraction, consolidation, embeddings, reranking, query understanding, active recall, answers, storage, and backups. Report cold and warm caches, foreground latency, and background processing latency separately. Complex retrospection permits multiple reads within an explicit total budget.

Rate-limit background work by tenant quotas, job priority, and backlog so one brain's history import does not block others' immediate writes. Model failures have bounded retries. If organization cannot finish, preserve original text and expose backlog rather than silently dropping it.

Operational metrics include event-acknowledgment failures, indexing lag, job retries, recall-state distribution, evidence coverage, context usage, total call cost, P50/P95/P99 latency, storage growth, and recovery time. Logs record identifiers and statistics by default, avoiding duplicate persistence of conversation content.

Measure performance, availability, RPO, and RTO under explicit hardware, data scale, and model configuration. The design cannot preclaim millisecond recall of all history or fixed-cost infinite history. Budget tests ensure bounded resources; quality tests measure what tighter budgets lose.

15 · Complete acceptance and experimental protocol

Acceptance covers cognitive behavior, protocol semantics, and operational reliability together. Each cognitive module needs an ablation without that module to establish whether it improves its target capability. Architectural complexity is not a substitute for effectiveness.

Replay conversations chronologically. Indexing must not see future messages, test questions, answers, or evidence labels. Split development and test data by complete histories or people, keeping paraphrases of one question together. Alongside public benchmarks, include unpublished Chinese conversational language, implicit cues, group chats, and long-term changes.

With the same answering model, persona, and input/output budgets, compare a recent window, rolling summaries, hybrid source retrieval, and the complete system. Treat full-history context as a separately costed reference. Repeat runs, report uncertainty clustered by history, and combine blinded human review with automated metrics rather than letting one model judge determine all conclusions.

Quality metrics include evidence recall, complete evidence coverage, answer correctness, current-fact errors, unsupported recall, appropriate clarification, excessive refusal, and implicit memory use. Report ordinary details as well as pinned memories; do not test only content the system already labeled important.

Acceptance thresholds follow two principles: deterministic semantics such as isolation, deduplication, versions, deletion, and budgets must satisfy their assertions; statistical quality must show reproducible improvement over the strongest baseline, with separate checks for regressions in key categories. Set numerical thresholds by application risk and sample size; do not describe unrun experiments as achieved capabilities.

16 · Architectural decisions and choices requiring validation

The cognitive memory implementation blueprint maps current source code to data reuse, inference lifecycle, semantic consolidation, hybrid recall, durable jobs, host control, and acceptance dependencies. It is an implementation design, not evidence that the new mechanisms are complete.

Architectural decisions: an independent memory runtime; separate cognitive modules; original events distinct from interpretation; relational authoritative storage with rebuildable indexes; fast writes and slower consolidation; host lifecycle integration alongside active tools; orthogonal retention, activation, evidence, and scope; common core and formats across deployments.

Decide through experiments: episode boundary algorithms, embedding and reranking models, activation and decay parameters, association depth, context selection, consolidation triggers, conflict detection, semantic support judgments, and budgets for different languages and agent types.

Decide through adapter validation: which events each host captures; whether it supports pre-response injection, pre-output version checks, delivery states, branches, and compaction handoff. Report verified compatibility rather than inferring full support from MCP support.

Implementation organization: separate domain objects and policies, application flows, persistence and model ports, HTTP/MCP adapters, host connectors, workers, console, and evaluation. Base-model providers, embedding providers, and graph retrieval policies are replaceable. Database transactions, authorization, and deletion semantics are not delegated to models.

This specification does not divide the complete goal into demo releases. Implementation still follows dependencies, and completion is judged against every agreed capability and acceptance result. Status reports must clearly identify work that is not implemented or not validated.

17 · Research and technical foundations

The following sources support functional inspiration or technical constraints. They do not validate the complete system proposed here.

The 2026-10-23 research supplement: 25 papers, nine cognitive mechanisms, and architectural implications expands on event segmentation, context reinstatement, conditional beliefs, shared patterns and individual differences, selective review, and procedural learning, including evidence limits and proposed controlled experiments. It presents design recommendations, not implemented capabilities.

  1. McClelland, McNaughton, and O’Reilly (1995): complementary learning systems. Supports a functional division between rapid learning of experiences and slower learning of regularities.
  2. Baddeley (2000): the episodic buffer. Theoretical inspiration for integrating current information and long-term memory within a limited workspace.
  3. Tulving and Pearlstone (1966): availability versus accessibility. Cues can improve recall of some content unavailable to free recall; this does not mean all forgetting is reversible.
  4. Official ACT-R reference manual. A reference for activation and cognitive modeling, not proof that this system's parameters are biologically valid.
  5. Hupbach et al. (2008): context-dependent memory updating. Recall and updating depend on experimental conditions; not every retrieval rewrites history.
  6. MemGPT. Active management of limited context and external memory.
  7. Generative Agents. Experiences, reflection, retrieval, behavior, and limitations involving missed retrieval and fabrication.
  8. LongMemEval. Long-term information extraction, cross-session reasoning, temporal updates, and abstention under uncertainty.
  9. LoCoMo-Conv. Implicit cues, compositional recall, and memory use without explicit restatement.
  10. Official MCP architecture. Responsibilities and context boundaries of hosts, clients, and servers.
  11. Official pgvector repository. Vector storage in the same database and the differences between exact and approximate retrieval.
  12. PostgreSQL row security. Scope isolation and bypass behavior for superusers, BYPASSRLS, and table owners.
