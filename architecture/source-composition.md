# Source-faithful composition

`source-composition-v1` extends `recall-resolution-v1`; version 2 also covers ordinary claims and their short views. Version 3 adds source-rendered communication views, and current `source-composition-v4` shares full sources in general verification. These contracts address observed failures: an autobiographical draft can invent circumstances after correctly recalling a scene, and compressed descriptions can assign one person's actions to someone else. Authentic citations and correct speaker attribution alone do not establish either kind of fidelity.

The shared composition procedure fixes the event's participants, actions, objects, expressed meaning, time, frequency and qualifications before changing its wording. It applies to complete answers, including captions, letters and other drafts in the user's voice. Modifiers, possessives, pluralization and habitual expressions can introduce facts, so the check covers those phrases as well as main verbs. When a paraphrase cannot be supported confidently, the model should retain or quote the source wording. The procedure stays out of ordinary user-facing responses.

Episode verification adds a fifth required facet, `organization_fidelity.participant_actions`. `attribution` still checks the communication's speaker and epistemic scope; the new facet checks the actors within the reported scene. Coordinated titles must not attach several people's actions to one subject. If the ordinary wording permits an unsupported actor assignment, the verifier must return `unknown` rather than repair the statement or adopt a charitable interpretation. A broader topic description is acceptable when more specific roles cannot be established.

The existing independent verification call returns this facet together with the other four. Missing fields fail schema validation; `unknown` and `contradicts` veto publication even when every other verdict supports the proposal. Publication rechecks the retained assessment against the same versioned input contract. No additional model call, lexical actor classifier or new default paid answer reviewer is introduced. New bounded history jobs retain participant-action constraints for claims but omit episode-operation instructions because their schema cannot propose episode actions. They do not receive the host's autobiographical writing procedure. This keeps processing within existing byte limits; no request or allocation ceiling is raised.

Version 2 requires `participant_actions_verdict` for every non-episode proposal. It checks the full statement and any `recall_summary`, including assistant drafts in the user's voice. Missing assessments and adverse verdicts block publication, which rechecks the retained verdict. The existing verifier call supplies this assessment. This covers the version-1 assessment gap exposed by an ordinary `agent_said` claim that reassigned the user's chalk-marking action to Aunt Mara; it does not guarantee that a positive assessment is correct.

The [subsequent real-model diagnostic](../evaluations/v1-2026-10-26-source-capsules.md) exposed a version-2 failure: both a claim and an episode assigned the first person inside a user-voice draft to the assistant, and their verifiers incorrectly approved it. Local encoding did not include the earlier explicit voice-setting request. Merely adding another instruction or treating every quoted draft as a real action would not resolve this failure.

## Source-rendered communication views

Version 3 separates remembering delivered text from narrating the actions inside it. For `agent_said`, `proposal_offered` and `commitment_expressed` claims, the processor first validates the original proposal and all source references. It then renders `statement` from the exact selected positive excerpts as attributed JSON-quoted communication, explicitly leaving embedded speakers unresolved. It omits a generated `recall_summary` for these speech claims so a second paraphrase cannot reintroduce the same actor substitution. The model still selects excerpts, memory kind and retention; its claim kind, world, conditions, timing, source eligibility and counterevidence remain subject to the existing independent checks. Quoting a promise in a draft does not establish an actual commitment.

The rendered proposal, rather than the model's free paraphrase, goes to independent verification. The raw response fingerprint remains unchanged. Publication recomputes the view from the validated source versions and rejects a different statement or a reintroduced free summary even if every retained verdict says `supports`. An overlong complete quote is rejected as a derived proposal; it is never clipped to fit 2,048 characters. Original captures remain stored. User/operator factual reports and their supported personal short views continue to use semantic encoding.

Episode actions whose effective membership includes an assistant source similarly receive a source-rendered organization statement containing complete member contributions with their recorded roles. If those complete quotations exceed 2,048 characters, the view describes only the source-role counts and points to the original members, without an inferred topic, actor assignment or external outcome. Membership, ordering, transition and boundary checks still apply, and the existing verifier must assess the actual proposed grouping against all member sources; mere adjacency is insufficient. User-only episode organization is unchanged.

This is deliberately conservative about generated speech. Communication views can be longer than paraphrases, and a large interaction can have a less informative navigation label. No token-saving claim follows from this change. It adds no model call, narrator classifier, source mutation or database migration. Old jobs retain their frozen contract and old assertions are not silently re-encoded. The repair prevents this class of free-paraphrase substitution in new assistant communication claims and mixed-source episode labels; it does not establish a universal narrator resolver, prove positive semantic verdicts correct, or by itself pass the real-model release gate.

## Shared verification sources

The [version-3 fresh campaign](../evaluations/v1-2026-10-26-communication-views.json) stopped on its first general-mode encoding: twenty citations repeated only two source versions, producing a 121,913-byte verification request against the existing 98,304-byte ceiling. The request was refused before provider dispatch; the known proposal remained charged. Local/history verification already shared its complete context, but general verification still repeated full records beside every reference.

Version 4 applies `shared-verification-sources-v1` to general and orientation verification. Each numbered citation retains its original index, exact excerpt, source hash, span, relationship and proposal-specific authority. Its inline source becomes an exact event/version `source_ref`; complete original records appear once in `verification_sources`. Source identity conflicts, hash mismatches and excerpt mismatches fail before dispatch. Complete qualifications remain available, and another proposal's citations still cannot supply a positive premise. Local/history contexts are not projected a second time.

The [paired recorded-data replay](../evaluations/v1-2026-10-26-shared-communication.json) preserves all twenty references and both complete source records while reducing that request to 59,359 bytes under the same limits. It uses synthetic callbacks, not real-model acceptance. Version 3 still produces its original over-budget request; old frozen prompts and failed operations remain unchanged. The change adds no model call, truncation, authority or allowance. It does not establish a general token-saving rate or prove that a real verifier will assess the shared sources correctly.

Version 2 explicitly permits either `event_revision` or `revision` in claim, situation-update and belief-link source citations, with exactly one spelling. Both spellings together are rejected. Only this declared alias is canonicalized after raw schema validation and before independent verification. Event identity, version, content hash and source spans still undergo their original checks. The raw response fingerprint remains recorded; memory versions, episode members and literal user values are never rewritten. Shared citation schema definitions avoid repeating the same shape in every group, while retaining the existing condition and validity definitions and byte ceilings. Old contracts do not acquire this alias or schema projection.

The host consumption protocol is `memory-consumption-v8`, and the optional answer review policy is `answer-grounding-v4`. The latter includes actor-action fidelity within its existing memory-fidelity dimension. Applications must supply the host protocol or use `BrainRuntime`; an MCP tool installation alone cannot force an arbitrary host to follow these instructions. The host and semantic verifier remain fallible models. Structural checks enforce required assessments and adverse verdicts; they cannot independently prove that a positive semantic verdict is correct. Whole-answer and source review in the release scenario tests that remaining behavioral boundary.

## Bounded original-source context

Literal fragments can match a scene while omitting a distant sentence expressing why it mattered. `bounded-source-context-v2` can expose complete original user/operator messages already reached through validated recall leads: at most four messages, 2,048 UTF-8 bytes each and 4,096 bytes combined. It examines at most eight source identities and performs no additional source fetch or model call. Complete messages are admitted or omitted; they are not clipped through qualifications. Context-budget admission can fall back to individual records.

Version 2 can replace duplicate literal wrappers and verified plain episodic reports with their complete original communication. An eligible report is an episodic `episode_fragment`, explicitly `reported_fact` or `reported_preference`, with aggregation, no intermediate memory dependencies, always conditions, unknown validity and no procedure. Explicit occurrence time, typed conditions, inference, summaries, belief groups, disputes, counterexamples, pins and open commitments retain their metadata and existing projections. Version-1 passages keep the earlier literal-only behavior. Raw records remain in `items` and storage; this is context assembly, not deletion or an assertion that paraphrases prove truth.

The quote is communication context, not a new stored claim, an instruction or independent proof of external truth. It retains actor, delivery, world, recording time and a full-span `context_only` reference. Source hash, revision, permission, historical cutoff, cue descendants and superseded evidence are checked. A superseded sibling span blocks the whole quote. Explicit summary, valid-time and selected-memory reads do not expand to whole messages; an existing short presentation prevents expansion of its source. Removing visible anchors removes their quote. Original sources remain stored until explicit erasure.

Lexical topic frequency groups representations by their positive source identities, so storing several paraphrases of one experience does not count as several independent occurrences. This affects candidate ranking only; it does not establish truth, importance or recall sufficiency. Version-2 encoding guidance asks the model to choose coherent scene-and-meaning records and useful short views. Neither guidance nor a source quote proves automatic personal gist formation; that remains an empirical acceptance question.

The SQL candidate admission route also groups eligible literal/report versions sharing one exact positive source span, scope and world, provided a literal member is present. These source units share the soft candidate quota. One lead from each selected unit seeds neighborhoods; final admission retains their versions in rounds, with the existing hard cap of 128 versions. It does not merge stored records, sum confidence or drop typed belief metadata. The existing lexical scan, source, dependency and context ceilings remain. This prevents duplicate versions from consuming the candidate pool before an older matching source can reach context assembly. Source-unit admission and context deduplication are separate: an observed calendar-recall failure required both repairs.

Old cognitive input contracts keep their previous schemas and prompts. New jobs select the new contract; old retained assessments are neither upgraded to five-facet verification nor rejected simply because a later contract exists. Both recall-resolution contracts preserve their verified short-expression behavior. Original observations and full statements remain stored; no automatic re-encoding or age-based deletion is performed.
