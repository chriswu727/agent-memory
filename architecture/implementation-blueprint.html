Design status and source-code integration points

Design baseline: b2f12bb. All new types, fields, modules, tables, and actions described here are proposals. This document does not add those capabilities to the existing runtime. This work comprised source review and implementation design; it did not run real-model quality experiments or modify the database.

Extend the existing automatic read/write flow so persistent current situations drive recall, recalled material informs every inference, actual outcomes update the situation, and local long-term learning follows. Workspace management, episode organization, conditional beliefs, methods, and forgetting share one provenance chain. Do not create a separate “brain database” disconnected from original records.

One cognitive cycle, two computation schedules

Persist actual input→Propose current situation→Recall and expand→Bounded context→Model / tool / delivery→Reconcile outcomes and queue learning

The foreground performs only understanding and retrieval necessary for the turn. Background work handles cross-episode generalization, boundary revision, associations, and method updates. Background failure does not revoke accepted input or confirmed delivery or mark them as never having happened. Related source text remains readable and organization progress remains visible.

Foreground flow

  1. Capture. Reuse observe source keys, versions, and transactional enqueueing. Persist user input on receipt; cancelling a response cannot cancel that actual input.
  2. Orient. Read the branch's SituationState and form an OrientationPlan with current goals, reference candidates, unfinished matters, recall needs, and boundary cues. Code handles explicit identifiers and order; models participate when ambiguity exists. Orientation can share one request with initial recall planning rather than requiring a model call per module.
  3. Recall. Retrieve through multiple paths and expand episodes, fragments, or sources as needed. Code controls scope, budgets, and evidence; the model proposes only search, selection, or stopping actions.
  4. Compose. Save a reconstructible ContextPlan for the host's model invocation. Label original messages, workspace inferences, and historical evidence separately.
  5. Collect outcomes. Save model drafts, tool requests, actual tool results, and actual delivery or cancellation. For another tool-loop step, create the next invocation and use the latest situation.
  6. Commit. Reconcile proposals against actual outcomes, then CAS-update working state, record feedback, and idempotently enqueue relevant learning jobs in a short transaction before ending the turn.

Store current situation inferences in the invocation plan first; they must not overwrite committed completion state before generation. Do not require another semantic model check after delivery: immediately commit states established by actual receipts, and queue uncertain semantic changes for verification. Subsequent inference can still see the actual event tail.

The relationship between turn and invocation

Existing turn phases are strictly linear; do not move generated back to prepared to run tools. Add an invocation journal within each turn. A turn contains multiple invocations, each with its own input, orientation, recall plan, context, model request, and result. Stable call IDs link tool requests to results. Synchronous BrainRuntime.respond() remains available as a convenience adapter with one final-text invocation.

Use persistent sequence numbers and a leased active slot for each conversation/branch so two turns do not issue conflicting results from the same working revision. Record interruption or preemption explicitly; different branches may run concurrently. State CAS remains the final defense rather than relying solely on client-process locks.

Reuse authoritative storage and add organization and runtime state

memory_events continues to store actual source content. Semantic fragments, outlines, anchors, conditional beliefs, and methods reuse memory_assertions versions, provenance, world type, support paths, and derivation links. A concept can have its own representation without its own database.

New tables provide rebuildable organizational indexes and runtime guarantees, not new factual authorities. Pattern and counterexample references join event_ids / memory_ids derivation invalidation, with exact versions in documents. There is no prerequisite for a general graph database or arbitrary-object framework. Navigation edges and support edges must remain separate: co-occurrence helps search but does not establish truth.

Separate semantic versions from retrieval scheduling revisions. Call counts and accessibility changes do not rewrite assertion semantics or continually advance the brain-wide dependency_generation. Explicit correction, deletion, and revoked permission remain immediately invalidating; an ordinary new view is not a source correction. Initially retain the conservative brain-wide invalidation barrier; finer dependency invalidation later requires independent concurrency validation.

All new tables inherit tenant, owner, brain, and forced row isolation; objects also follow conversation, branch, and real/simulated scope. Import, export, correction, deletion, restoration, and redaction must cover new organization, plans, vectors, and job results, not only core tables. Logical deletion blocks queries immediately; pending computation must not republish deleted sources.

Target shape of a conditional belief

memory_kind: semantic
representation: schema
claim_kind: inferred_preference
statement: When discouraged during exam preparation, the user tends to prefer conversation before revision planning
conditions: task = exam_preparation AND situation = setback
epistemic_status: inferred
valid_time: Evidence-supported interval; unknown bounds remain unknown
supports: [Source fragments and their fixed versions]
counterexamples: [The fragment explicitly requesting immediate planning this time]
derivation: Model/rule version, dependency assertion versions, root sources
review_state: supported_inference / contested / pending

This is an internal structure sketch, not a currently submittable API object. Conditions use a bounded expression structure without side effects and evaluate to true, false, or unknown; unknown is not a match. Model-inferred emotion can only represent the situation at the time with provenance and uncertainty, not automatically become a permanent label.

How understanding and consolidation execute

Episode formation

Retain the literal capture path in classify_segments / extract_event. Add an EpisodeEncoder that reads the current open episode, bounded new sources, and orientation cues to propose continue, close, split, or reopen. Goals, participants, task state, and substantial gaps provide boundary signals; use hysteresis to avoid repeated segmentation on minor topic shifts. A large event may contain multiple fragments, and both boundaries and membership may be revised.

Episode formation runs per conversation branch. Typed associations connect the same project or relationship across conversations without merging all records into an ever-growing context. Childhood described by the user is a reported user experience, not the agent's childhood. Every fragment preserves roles, negation, conditions, time, and world type.

Generalizations and counterexamples

The Consolidator processes only new or affected episodes. It first retrieves nearby existing beliefs and counterexamples, then proposes new conditional beliefs, situation splits, one-off exceptions, explicit supersession, or continued uncertainty. Proposals pass source/version checks, semantic support verification, and publication policy.

Code checks IDs, source offsets, scope, world, versions, dependency cycles, source deduplication, and structural completeness. Semantic verification judges whether the source supports, contradicts, or cannot establish the minimal claim. Model verification can still fail; it reduces error rather than proving facts. Publication preserves statuses such as inferred, reported, and contested. A valid evidence ID alone does not authorize arbitrary generalizations in the workspace.

Explicit corrections must affect responses without waiting for slow consolidation. Explicit correct requests use existing invalidation immediately. Suspected natural-language corrections first affect the current situation and mark identified old beliefs for review; background work revises only affected scope. If the target is unclear, preserve the conflict and clarify rather than clearing knowledge about a person after a vague negation.

One source remains the same root source through multiple summaries or assistant restatements. Root deduplication prevents mechanical duplication but does not prove statistical independence between distinct sources. Explicit user confirmation must bind a specific claim; one “yes” cannot confirm every claim in a preceding paragraph.

If a counterexample is deleted or corrected, generalizations whose scope depends on it must also be invalidated and checked. Removing a counterexample must not automatically strengthen “in some cases” into “always.”

Shared patterns and instance differences

Implement shared patterns first as grounded view references. A pattern contains common claims and qualifiers; an episode stores the fixed pattern version, its own members, and exceptions. Reuse only fields supported by this instance's sources. Common pattern details cannot become observations of this instance. Without evidence of a ten-minute conversation, the instance cannot acquire that duration merely because many others had it.

The expander combines actually stored claims rather than asking a model to generate missing history. Check equivalence of claim sets, negation, time, conditions, roles, and provenance before and after compression; retain unsafe-to-share portions unchanged. This check does not prove natural-language claim extraction is fully correct; extraction quality still needs model evaluation. Old episodes reference pattern v1; publishing v2 must not silently alter them.

Separate latest/current pointers from version validity. Exact dependency expansion may read a historical pattern version that remains valid and has not been corrected or deleted; current-only queries and blanket rejection of superseded parents cannot apply unchanged. If factual correction or source invalidation revokes v1, dependent old episode views must also be invalidated and rebuilt from valid original fragments. Fixed versions cannot bypass correction. An old pattern explains an old representation; it does not automatically become a currently valid belief.

Methods and future matters

Procedural beliefs reuse assertions, but their evidence must bind real attempts: task, environment version, actual steps, method version, tool calls, outcomes, and failures. Episode and invocation references can express attempts without another execution-history copy. Establish server-authenticated tool producers first; a model or ordinary request cannot self-declare verified_producer.

Methods retain applicability, steps, exit conditions, and failure conditions. One success supports that outcome alone, not a universal rule. Actual expressions and outcomes update commitments and open loops. Reminder retrieval is separate from execution scheduling; remembering a plan does not authorize the memory system to act.

From hybrid retrieval to grounded, bounded context

Find candidates, then validate complete support paths

CandidateRetriever obtains budgeted keyword, semantic, situational, and time/exact-reference candidates in parallel. Push authorization, branch, world, and historical-scope filters before top-k selection where possible so unusable candidates do not fill it. Combine rank fusion, event deduplication, and coverage selection while retaining per-path signals. A zero lexical score must no longer veto semantic candidates.

Semantic embeddings use separately versioned spaces, asynchronous batch construction, and content-hash deduplication. Editing an object removes old vectors from recall; keyword and source paths remain while new vectors are pending. Do not compare vectors with different spaces, dimensions, or content versions. Build projections and indexes within the same database according to actual configuration. External vector calls run outside transactions, and query failures return explicit degradation.

For selected candidates, separately batch-load a bounded source dependency closure, including parent assertions, patterns, counterexamples, and root events. Validation dependencies need not all enter model context, and parents need not first appear in top-k. Limit and record nodes, depth, and bytes read. On overflow, report incomplete verification and choose a smaller valid source representation rather than skipping evidence checks.

Controlled further recall

Retain RecallController and add typed actions such as search, expand_episode, inspect_fragment, follow_association, and finish. Expansion accesses only objects returned or verified by the server, with bounded depth, fan-out, and cumulative reads. “How long?” favors specific fragments; “What was that period generally like?” favors outlines. Explicit cues may search deep source text directly.

Current observations and historical evidence use separate channels. Current messages and new tool results can support present understanding, but query rewriting or a new invocation must not move the original historical cutoff. A cue and its derivatives cannot prove the history described by that cue. Source corrections, deletions, and revoked permissions still apply in their current state; a historical cutoff cannot bypass them.

Add claim_kind constraints on provenance. Delivered assistant speech can support agent_said, proposal_offered, and commitment_expressed, but not independently external_world_fact or task_completed. Drafts and unknown delivery cannot prove the user heard a commitment. Apply this rule to search, semantic generalization, working state, and feedback rather than patching only one entry point.

Workspace composition and recovery

ContextComposer first retains host system rules, current input, tool protocols, and required call/result pairs, then allocates active goals, open loops, recent messages, and relevant memories. Choose granularity for the current need instead of permanently reserving large blocks for each memory type. Do not remove exceptions, negation, or qualifiers to save tokens. If required content cannot fit, explicitly block or request host reduction rather than silently removing tool structure.

ContextPlan freezes representation versions, source sets, expansion scope, block order, format/policy/tokenizer versions, historical cutoff, and fingerprint. Recovery of the same invocation reuses that plan without reranking because of decay, background additions, or policy changes. If deletion or correction invalidates sources, block replay of the old plan and create one with a new attempt identifier while retaining accumulated cost.

Any content entering orientation or recall models may influence the result and belongs in influence dependencies, not just the final selected sources. Semantic plan text is protected memory data subject to deletion and export. Monitoring logs record only identifiers, state, and measurements, not content or hidden reasoning.

Measure the actual request when the host provides a tokenizer; otherwise retain a clearly labeled conservative estimate. The current code estimates tokens using UTF-8 bytes, which are not provider token usage or monetary cost. before_compaction can identify replaceable history only when sources are persisted, working state and unfinished tool structures are reconstructible, and necessary tail content has a supplemental read path.

Forgetting as an independent retrieval scheduling policy

AccessPolicy separately manages accessibility, utility, retention value, evidence state, and content availability. Calculate recency and usage-spacing effects lazily at query time, without hourly full-database scans or model calls for ordinary demotion. Weights and thresholds are policy parameters calibrated under the same tasks and budgets, not a presumed universal human forgetting formula.

Retrieval hits, context inclusion, citation in a delivered response, explicit user confirmation, correction, and actual task outcomes are different feedback types. Ordinary access updates scheduling only. Usefulness is not implied by use; background self-assessment adds no evidence. Actual outcomes trigger utility reassessment, but high utility is not high truthfulness. Deduplicate feedback idempotently by turn, source, and feedback event.

Ordinary representations gradually leave the everyday candidate pool but remain expandable or deeply retrievable through valid cues. Protect important specific fragments, rare exceptions, and unfinished commitments. Preserve event diversity so popular generalizations do not monopolize context. Granularity and accessibility remain independent: a detail can be easier to recall than a generalization.

Automatic physical erasure remains disabled by default. Cognitive fading is not deletion. Actual deletion follows authorized requests and retention policies and propagates through all dependencies; patterns, differences, and background jobs cannot restore deleted details. Any future policy that erases source text while retaining lower-resolution beliefs must first define retained scope and evidence state, rather than equating that with complete deletion.

Budgeted durable jobs and publication protocol

Short transaction: claim a job
  Check identity scope, deduplication key, and execution eligibility time
  Set lease_token / lease_until / fence / attempt
  Freeze source versions, target versions, input fingerprint, and policy version
  Reserve model / embedding / retrieval capacity for this attempt
Outside the transaction: read authorized input and compute
  Check timeout, output size, and structure
  Save pending results together with source dependencies
Short transaction: attempt publication
  Validate lease fence, source versions, permissions, and deletion state
  Validate target expected_revision and support paths
  Idempotently publish assertions / membership / associations; update job and actual usage
  Changed sources: invalidate results or requeue against new versions

Jobs move through queued → leased → completed, with separate retry_wait, superseded, cancelled, and failed states. An expired lease can be reclaimed; an old worker returning later cannot cross the fence to publish. A completed model call with a lost response is unknown. Keep its budget consumed or pending settlement rather than automatically refunding and retrying indefinitely. Prefer provider request reconciliation when supported; otherwise each new attempt consumes the same overall budget.

Track reservations and actual usage for orientation, recall, semantic verification, consolidation, embeddings, and method learning by logical operation ID and request fingerprint. Foreground controls apply per invocation/turn; background controls apply per brain and configured window. Hosts report tool and primary-response costs with coverage labels. Missing provider usage or pricing is unknown, not zero cost.

Cognitive jobs receive only new fragments and bounded relevant knowledge. Deduplicate and coalesce to reduce repeated work. Prioritize correction/deletion work while preserving progress for ordinary jobs to avoid starvation. If backlog exceeds budget, reduce organization frequency or report coverage limits rather than placing all history into the next response.

Preserve the existing meaning of indexed_sequence as literal extraction progress. Event segmentation, semantic beliefs, and vector projections have separate progress and coverage. Slow generalization must not make all persisted, source-readable content unavailable. Answers need not wait for every cognitive index to finish.

Module integration, host capabilities, and monitoring

New internal responsibilities may live in cognitive_control.py (orientation and orchestration), episodes.py (episode organization), consolidation.py (belief/method proposals and verification), retrieval.py (candidates and expansion), dynamics.py (scheduling), and workers.py (job protocol). Existing cognition.py retains deterministic evidence rules and compatibility entry points; service.py owns authenticated application operations and transactions. Avoid putting all new logic in one large file without requiring a separate deployment per module.

Define replaceable semantic-processing and embedding ports, following the existing provider-adapter approach. The host still configures the primary model; memory-understanding models may be configured separately or reuse its provider. One call may batch multiple related proposals, rather than imposing a paid call for every segmentation, summary, and reflection layer. Model-generated objects always enter server publication as proposals.

Integration binds a stable brain_id, host adapter, and model configuration. The adapter then automatically handles message capture, pre-inference context, actual outcomes, and recovery. HTTP and SDK expose the same core; MCP supplies supplementary retrieval, corrections, and diagnostics. Without control of the host lifecycle, report only actual capabilities.

Full host integration covers input, message revisions/deletions, every model call before and after execution, tool calls and results, actual delivery, cancellation, before/after compaction, recovery, branches, and external feedback. Store capability declarations separately from verification results. Hosts still authorize and execute tools; memory cannot expand permissions through old statements.

Add only authenticated observability necessary for development: invocation/job phases, queue coverage, degradation reasons, object versions, source-expansion entry points, foreground/background budgets, actual usage, retries, and unknown outcomes. Reuse existing monitoring interfaces without making a management page a product dependency.

Complete implementation in dependency order

Organize work by dependencies rather than demo releases. Every chain ultimately joins the same automatic runtime; do not deliver isolated memory functions requiring manual user calls.

  1. Complete execution and evidence foundations first. Add migrations and contracts; short-transaction jobs, leases, and unified budgets; separation of candidates and dependency closure; and claim-specific evidence validation. Include correction, deletion, export, and restoration for every new object.
  2. Connect present understanding and episode formation. Extend WorkingState, persistent orientation plans, and EpisodeEncoder. User input automatically affects the current workspace; episode organization may lag with a supplemental read path.
  3. Connect conditional beliefs and recall. Add counterexample-aware semantic proposals and verification, hybrid semantic/keyword candidates, episode expansion, and on-demand representations. Verify their effect on the next answer.
  4. Add long-term change. Versioned patterns and individual differences, accessibility policies, utility feedback, and local review must preserve details, exceptions, and sources through generalization.
  5. Complete action loops and host lifecycle control. Invocation tool loops, trusted outcomes, procedural learning, prospective matters, streamed delivery, and compaction recovery must ship with the related logs and migration support.

Semantic storage/workers and host invocations can proceed in parallel. Conditional generalization depends on the former, procedural learning on trusted results, and full compaction control on reconstructible working state. Use incremental migrations, retaining reads of old literal representations and single-text invocations. Contract changes must update Python, TypeScript, MCP, and packaged resources together. Background backfills of old data must not block normal reads and must record processor versions.

Deterministic acceptance without model usage

Extend existing cognition tests, evidence-boundary tests, semantic-runtime tests, storage tests, adversarial tests, and turn-recovery tests. Use controlled providers to verify these invariants:

  • Semantic candidates with zero lexical overlap are not wrongly removed; parents outside the candidate set still undergo bounded verification.
  • Unknown conditions are not matches; different situations can coexist; delivered commitments and completed tasks require different evidence.
  • Expansion of patterns and differences preserves extracted claims, qualifiers, and provenance; patterns do not fill unsupported fields.
  • Fifty internal restatements do not increase root-source count; utility and accessibility updates do not modify truthfulness.
  • Corrections, deletion, permission changes, or expired leases during worker model computation prevent old publication; retries do not double-commit or escape budgets.
  • Recover the fixed invocation context; concurrent turns on one branch do not overwrite each other; learning failure after actual delivery does not resend a response.
  • Drafts, simulations, and unauthenticated tool results cannot become actual completion; duplicate outcomes bind idempotently by attempt.
  • Provenance, corrections, deletion, and unfinished matters survive export/restore and semantic-model or vector-space migration.

Validate real-model effectiveness separately

Fix the answering model, data order, and total budget to compare gains from a literal baseline, hybrid retrieval, episode situations, conditional generalization, and pattern compression. Metrics cover implicit cues, false premises, same-name people, long-term preference changes, exceptions, answer errors and coverage, method transfer, context, and total cost. Split by complete histories so test questions cannot influence encoding.

Controlled-provider tests establish execution and boundaries, not real semantic understanding or long-term memory quality. Paid-model or subscription-usage experiments require separate explicit user consent. This design work checked documents only; it did not run the proposed functional tests, cognitive experiments, or cloud CI.

This blueprint maps existing research targets to source-code integration points and verifiable behavior. Parameters, model choices, and effectiveness figures await measurement. Proposed code and database objects were not implemented during this design work.
