# Bounded retrieval of conversation context

The [stopped v5 evaluation](../evaluations/v1-2026-10-25-longitudinal-v5-stopped.md) exposed a gap between storage and use. A short duration preference was safely stored, but its text shared no query terms with a later planning request. No persisted association or episode linked it to the topic. Unrelated candidates occupied the final context while an older assistant suggestion remained visible.

Keyword retrieval now retains relative query coverage when combining routes. Reciprocal rank alone had largely erased the difference between a substantial match and a single shared word. Within the bounded lexical candidate set, each keyword contribution is multiplied by its coverage divided by the largest coverage. Semantic vector ranking remains independent. These values express retrieval priority, not confidence or factual support.

Association and episode expansion inherit half the strongest directly matched seed's score. Multiple paths do not accumulate additional association credit. Seed versions are excluded before the expansion row limit, so membership cannot boost a seed's own score or consume slots intended for neighbors. Expansion remains one hop; newly found memories do not become additional seeds.

For `continue_conversation`, an additional source-neighborhood route considers at most eight direct seed memories and sixteen source events. It follows only valid supporting references, then considers the previous and next current source records in the same non-null conversation and exact branch. Hidden, removed or out-of-boundary records are barriers rather than permission to skip further through history. At most sixteen neighboring events and sixty-four assertion rows are considered. Candidate memories retain their own exact supporting source references; contextual adjacency never becomes evidence for a semantic assertion or a persisted relationship.

The source route checks current source versions, content hashes, scope, visibility, superseded spans and the sequence boundary. Existing recall validation subsequently enforces query exclusion, historical evidence boundaries, world, lifecycle and dependencies. Explicit model-selected recall plans do not expand automatically. Direct retrieval for other intents does not use source adjacency. Age and externally observed usage still affect final access priority.

Bounded candidate search and missing source data have separate coverage flags. Exhausting a candidate cap reports partial scope without pretending that a completely loaded event tail is unread. Missing source data or incomplete dependency closure still prevents the stronger read-fence guarantee. This distinction matters when a newly observed message has not yet reached the index.

The runtime preserves its existing context ceiling. It does not enlarge the host context, call another model, rewrite stored beliefs or require an embedding provider. Candidate truncation remains visible. A nearby message can concern a different subject; adjacency is a bounded navigation heuristic, not a guarantee of relevance. Final answers and source selection therefore need independent evaluation, including topic changes and short replies that depend on earlier conversation.
