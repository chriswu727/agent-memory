# Link-derived historical comparison accounting

The first finite acceptance attempt stopped on an internally contradictory proposal. A relation named two historical endpoints, but the model declared one corresponding comparison unchanged. The strict validator correctly refused publication. The [failed attempt](../evaluations/v1-2026-10-25-acceptance-attempt-1.md) remains a failure; its exact request and response are retained in an offline regression fixture.

The `history-link-coverage-v1` input contract removes redundant model bookkeeping. In historical integration, the model supplies its proposed claims and `belief_links`, plus `integration_abstentions` containing an objective ID and an allowed reason for each selected objective with no proposed link. It does not emit `integration_decisions` under this contract.

The runtime matches each manifest target's exact memory ID and revision against relation targets. Every matching link is assigned to every covered objective. A link can therefore cover multiple objectives without asking the model to list the same link repeatedly. Every uncovered objective still requires an explicit abstention; absence is not an assessment. A covered objective with an abstention is a contradiction and is rejected. Unknown, duplicate, missing, malformed or mixed-version accounting is rejected, as are links unrelated to every selected objective.

Derived decisions pass the existing strict incidence validator and retain the same internal monitoring format. This calculation establishes only which comparison a proposal addresses. It does not establish semantic support, source permission, current applicability or publication. Full endpoint evidence, attribution, conditions, time, source versions, independent semantic verification and publication-time validation remain required. Rejected relations cannot publish their dependent claims. Proposed, assessed and published coverage remain separate.

The new version inherits relation capabilities, source-backed episode navigation and speech-event guards. Earlier input versions retain their original schemas, prompts and strict decision validation. A recorded failed paid result is never rewritten or retried by this change. Request sizing uses the selected version's actual schema and instructions; per-phase and per-root allowances are unchanged, and accounting adds no model calls.

The [local verification record](../evaluations/v1-2026-10-25-link-coverage-repair.md) includes the exact original request replay and preserved rejection. A separately labeled deterministic candidate response exercises the new wire format, semantic rejection, full publication checks and unchanged source guards. These tests establish protocol behavior, not real-model accuracy. Real-memory acceptance remains open until the frozen follow-up campaign and its independent review pass.
