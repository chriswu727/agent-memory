# Historical feedback and tentative suggestions

The [retrieval diagnostic](../evaluations/v1-2026-10-25-retrieval-continuity.md) recovered a user's feasibility preference without fixing the next answer. The host still favored its earlier, longer proposal. The preference's current applicability was unknown; the existing interpretation protocol permitted historical reporting but did not distinguish using that history to suggest an option from declaring it a settled current rule. This was a protocol ambiguity, not proof of the model's causal reasoning.

`memory-consumption-v4` distinguishes these uses. When a current request resumes a task and available source context connects earlier user feedback to it, the host may use that feedback to form a reversible tentative suggestion. It must preserve attribution or express a condition when needed. Unknown applicability alone need not force the user to repeat useful background. An assistant's earlier proposal is an offer; its detail does not establish user adoption or priority over the user's own feedback.

This permission does not change stored memory, applicability or belief-resolution states. It cannot override false applicability, conflicts, explicit retractions or current changes. Retrieval does not establish relevance by itself. The host must not transfer feedback across unrelated tasks or speakers, or treat quoted, hypothetical or fictional statements as the user's own preference. Ambiguity that materially changes the suggestion still requires clarification. Unknown remains undetermined; recency alone cannot resolve a conflict. External completion and successful storage still need their own evidence.

The optional `answer-grounding-v2` reviewer shares the same permission through a common trusted instruction constant. Embedded host instructions remain review data, not reviewer authority. The new reviewer has a new fingerprint. An old bound pending review or approved-but-undelivered draft cannot silently acquire new authority; existing version and binding checks stop that transition. Already completed turns retain their normal replay behavior.

Deterministic tests verify instruction delivery, unchanged state labels, review binding and restart behavior. They do not establish model obedience. Real behavior must be evaluated with frozen inputs, explicit negative controls and one bounded response per case. The original failed answer remains failed regardless of a later observation. No model call, automatic rewrite loop or larger context budget is added to normal turns by this protocol change.

The [bounded verification report](../evaluations/v1-2026-10-25-preference-use.md) records three actual responses. They exercise historical feedback, an explicit current override and permanent-rule uncertainty. Whole-answer review still finds a present-state overclaim and an overconfident negative heading. The permission is implemented; complete longitudinal behavior remains unverified.
