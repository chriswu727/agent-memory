# Changelog

## Unreleased — 0.1.0 candidate

memBrain is a human-inspired memory engine for AI agents. It keeps persistent memory outside the model's current prompt and supplies relevant context through an explicit agent lifecycle. This candidate is not yet a stable release: longitudinal behavioral acceptance remains incomplete.

### Included

- Guided first use through `membrain plugin setup`: actual incoming-message status, host connection instructions, a cross-session exercise and local semantic-model retry without an extra API key.
- Saved notes refresh inside ongoing sessions after corrections, removals and coming-up changes. Fingerprints are bound to the selected brain, failed reads preserve the previous snapshot, and unchanged snapshots are not repeated. Previously delivered text cannot be retracted from a host model.
- Explicit questions about earlier assistant recommendations retain attributed speech recall even when complete user history is already loaded. Other people's recommendations do not enable assistant-speech recall.
- The local worker yields briefly while work remains, rather than imposing a one-second idle wait after every busy slice. Per-brain fairness and publication checks remain in place.
- Memory of a person's life (Phase B):
  - Typed notes: a note can carry a kind (person, constraint, preference, plan, routine, milestone, relationship, agent commitment), a person it is about, aliases, a plan status (intended, scheduled, done, cancelled), dates, pinned and sensitive. Notes are stored as plain text with a short header, so recall, the memory page and deletion work as before.
  - Every session starts with a `<membrain-coming-up>` block of plans and promises that are due soon, overdue or still open, and with notes grouped by kind and chosen by priority within the budget.
  - Alias names are used as recall cues, so "the sparky" finds the electrician.
  - Role-play memory is kept apart from real life: a role-play character gets its own memory for each person (proxy header `X-Membrain-Roleplay`, the AstrBot setting, `ChatMemory(roleplay=…)`), and real-life notes are shown in a role-play only when allowed and never when marked sensitive.
  - Likely duplicate notes are pointed out to the agent, and the memory page offers to merge them.
  - On two held-out scenarios scored blind, the plugin went from 14.5 to 18.5 of 22 cases, against 18 for the whole history in the prompt and 7.5 for no memory ([report](evaluations/v1-2026-10-29-phase-b.md)).
- Recall shows the reply that followed a recalled message (the answer to a recalled question, or the reaction to a recalled statement) and considers more candidates.
- In Claude Code, Codex and WorkBuddy, the `memory_recall` tool now returns the same compact recall as the hooks. It used to return the service's generic rendering. `with_ids` still returns memory IDs for the forgetting steps.
- `membrain plugin import` copies what Claude Code, Codex, Hermes and OpenClaw already remember about the person into notes, and session start skips imported notes that the host shows anyway.
- Benchmarks: a LoCoMo harness and report (76.2% on the conversations not used for tuning, against 81.2% with the whole conversation in context; [2026-10-29](evaluations/locomo-2026-10-29.md)), and a LongMemEval harness with the benchmark's own reader and judge prompts. On a 30-question LongMemEval sample memBrain tied the whole history in context, 22 of 30 each ([report](evaluations/longmemeval-2026-10-29.md)). The full 500 questions have not been run; see Known limits.

- Renamed the project to memBrain: distribution `membrain-ai`, command `membrain`, Claude Code plugin and marketplace `membrain`. Existing data directories, database and Docker volume names, the export format and `agent_memory` imports remain compatible.
- A Claude Code plugin and marketplace (`plugins/membrain`) installable with one command. Hooks record messages and final replies, add matching records from earlier sessions before replies, queue records while the service starts, and never block the host. No Docker or extra model key is required.
- An embedded PostgreSQL + pgvector database engine from the optional `embedded` extra, with the same schema, roles and row-level security as Docker. `desktop setup --database auto` selects it when installed; backup and restore keep the installation's engine. When run as root it uses a dedicated unprivileged account.
- WorkBuddy and CodeBuddy support in the same plugin package: a `.codebuddy-plugin` manifest and marketplace, a cross-platform hook launcher, and reading the final reply from the session transcript when the Stop hook does not include it. Claude Code's hooks and MCP file moved to `hooks/claude-hooks.json` and `.claude-mcp.json` so no host loads another host's files; verified again with Claude Code 2.1.312.
- OpenClaw plugin (`integrations/openclaw/membrain`) and `membrain plugin tool` for hosts without MCP. Not yet loaded by a real OpenClaw Gateway.
- `membrain proxy`, an OpenAI-compatible memory proxy for any bot that can set a `base_url` (live-stream VTubers, NoneBot, Koishi, LangBot, SillyTavern): per-person memory from the request's `user` field or headers, streaming pass-through, prompt-cache-friendly placement, and a token mode for serving other machines.
- AstrBot plugin and a shared chat-bot adapter (`membrain.adapters.chatbot`): per-person memory for bots on QQ, WeChat, Telegram, Feishu, Discord and other platforms, with group chats kept apart from private chats by default, per-person pause and note tools. Not yet run inside a real AstrBot installation.
- Windows fixes from a real-machine run: the recovery registry is flushed through a writable descriptor (Windows rejected the read-only `fsync`, so every new installation stopped at `database_initialization_failed`), and setup accepts the host adapter's `plugin/` state directory written before the first start (the AstrBot plugin could never complete its first start). The OpenClaw install instructions add `--accept-capabilities`, which OpenClaw 2026.10 requires.
- Foreground turns and background learning no longer invalidate each other. Recording a reply's delivery replaced its undelivered draft through the general source-edit path, which advanced the brain's dependency generation on every reply; every learning window or other turn running at that moment then ended in `context_stale` (35 times in the [2026-10-27 A/B run](evaluations/v1-2026-10-27-ab-baselines.md)). A draft is never evidence, so its delivery now leaves the generation unchanged unless something actually depended on it. The turn lease heartbeat also kept running after one failed renewal: a learning publication holding the brain row past the turn's 2-second lock timeout returned 503 once and the turn was lost for good. It now retries transient failures while the last renewal still covers the lease. Reproduced offline with deterministic cognition; no paid run has re-measured the A/B.
- Embedded databases created as root are kept inside the installation directory when the service account can reach it, so container data volumes hold them.
- Codex plugin: the same package installs in Codex (`codex plugin marketplace add chriswu727/memBrain`), with Codex-specific hooks (`--host codex`, `turn_id`, context limits) and MCP configuration. Verified with Codex CLI 0.165 against a stub model.
- Hermes Agent memory provider (`membrain.adapters.hermes`, entry point `hermes_agent.memory_providers`): notes and recent history in the system prompt, per-turn recall, turn recording, mirroring of Hermes's built-in memory writes, and `membrain_note`, `membrain_search`, `membrain_pause` and `membrain_resume` tools. Not yet run inside a real Hermes installation.
- Per-user memory for shared bots: `membrain.host` functions take `user_id`, giving each person their own brain (created with the new idempotent `PUT /v1/brains/{brain_id}`), their own spooled records and an optional per-user recording pause.
- A memory page for plugin users (`membrain plugin ui`): a single-use local link opens notes (add, correct, delete), conversations, search, recording pause, export and erase-everything. Notes written or corrected by the user are labelled as theirs and take precedence over the agent's notes.
- Privacy controls and a shared host layer: `<private>…</private>` spans and credential-like values are removed before anything is staged, spooled or stored; `membrain plugin pause|resume` and the `memory_pause` and `memory_resume` MCP tools stop and resume recording. Prompts are now stored together with their reply, so a turn in which recording is paused is not kept. Host-independent logic moved to `membrain.host` for adapters.
- Host-curated notes and message-level recall for the plugin: the host model saves short durable facts with the `memory_note` MCP tool (replacing outdated ones), and every session starts with those notes plus the user's recent messages with pasted code and logs compacted. Before each reply the hook shows complete earlier messages around the recalled statements instead of isolated sentences, uses the previous prompt as a cue for short follow-ups, and keeps only the closest meaning-only matches. Vector recall excludes assistant speech and interleaves the closest memories written in another script. The timeline endpoint filters by event IDs and conversation.
- Semantic recall without an API key: the optional `semantic` extra runs a pinned multilingual embedding model (`multilingual-e5-small`, int8 ONNX) in-process. The plugin downloads it in the background, the service backfills embeddings for existing memories, and hook and MCP recall fuse vector and keyword rankings, so questions in another language or with different wording can find earlier records. `membrain plugin fetch-model` and the `semantic_recall` status field were added; `MEMORY_EMBEDDING_LOCAL_DIRECTORY` configures the same model for server deployments. The desktop worker drains queued jobs for up to two seconds per round.
- Lexical recall folds common English word forms (`running`, `runs` and `ran` match `run`; `married` matches `marry`) for both scoring and database candidate search, which uses stem prefixes on the existing index. Retrieval version `unicode-lexical-v3`. Plugin sessions whose history exceeds the injection budget now show more earlier messages, each shortened, instead of a few long pastes.
- `membrain plugin` entry points for hooks, service start, MCP and status. Docker failures now include Docker's own error output.
- Persistent source-backed memory, working context, background learning, consolidation and cue-guided retrieval.
- Source-faithful composition instructions for autobiographical drafts, a versioned fifth episode participant-action facet, and required action checks for ordinary claims and their short views during verification and publication.
- Version-3 source-rendered assistant communication and mixed episode views preserve embedded draft voices as quotations, with publication-time source recomputation and unchanged user-report semantic encoding. Overlong communication remains available in original records instead of being clipped into a derived claim.
- Belief-neighborhood-v2 makes newly loaded relation endpoints inherit the strongest query seed in their own connected component. It prevents an unrelated correction from acquiring a fixed high rank and displacing relevant original sources; exact versions, evidence guards and explicit recall plans are preserved. The closed 26-input run retains its final recall failure; zero-model source recovery is not a new behavioral acceptance pass.
- Version-4 general verification shares complete source versions once, preserving every proposal's exact reference and authority while keeping older frozen wire formats unchanged. Existing local/history sharing is not duplicated.
- Bounded original-source context with source integrity, scope, correction, historical and granularity guards; source-origin frequency avoids counting paraphrases as independent experiences.
- Source-unit candidate admission and version-2 context deduplication keep repeated representations from crowding older useful source material out of recall, with unchanged hard bounds and qualified metadata preserved.
- A prospective schema-declared citation-version alias, shared citation schemas within unchanged byte limits, and accurate known-malformed-response accounting before evaluation stops.
- Task-specific cognitive instructions that preserve participant checks without sending unavailable episode operations or host writing procedures to bounded history processing.
- A varied release fixture with fourteen sessions, twenty-six inputs, source-bounded review, durable continuation and a planned model-callback change.
- The release fixture reserves 16,384 host output tokens for high-effort reasoning plus answer text after a preserved 4,096-token exhaustion; generic host defaults and old frozen plans remain unchanged.
- Python lifecycle integration, HTTP API, TypeScript client, optional MCP memory tools and direct API-key terminal chat.
- Scoped identities, corrections and deletion handling, bounded cognitive spending, and inspectable processing outcomes.
- Local setup, restart, upgrade, backup and recovery with an independently installed package; the verified desktop target is macOS with uv and Docker.
- Local retrieval and preparation optimizations without adding a separate model for memory admission.
- English and Chinese entry-point documentation, integration references and retained evaluation reports.
- Explicit semantic time allowances up to 600 seconds, with desktop response waits of 615 seconds for retained frozen jobs. The default 30-second allowance and existing 240-second reasoning preset are unchanged; proposal and verification still share one deadline.
- Versioned source-act interpretation for new captures and cognitive jobs, with unchanged old source/capture identities and legacy frozen request contracts.
- Scoped frequency-weighted lexical ranking, bounded adjacent source units, and comparable indexed/tail scores with access-age weighting.
- Assistant speech remains available for explicit speech/quote/episode/commitment requests with its own attribution label; it is excluded from ordinary personal recollection.
- Materialized episode-neighbor discovery to avoid a pathological nested join, plus language-neutral acknowledgment guidance and explicit remembered-detail boundaries.
- Source-preserving recall resolution: optional independently checked short expressions and model-selected retention, cue-driven detail expansion, inspectable original records, and no age-based content deletion or recurring summarization calls.
- Smaller bounded local-encoding prompts and schemas, unchanged frozen legacy requests, and explicit source-fidelity rules for autobiographical drafts.
- Prompt-aware memory allocation within the existing total input ceiling, a database compatibility marker for the new persisted representation, and a real subprocess-interruption regression for uncertain provider reservations.

### Known limits

Real-model observations still include historical information presented as current, irrelevant retrieved material and rejected valid semantic proposals. Earlier failed campaigns remain failed. See the [acceptance contract](architecture/v1-acceptance.md) and [closeout checklist](docs/releasing.md) for the remaining work and evidence boundaries.

The [completed varied diagnostic](evaluations/v1-2026-10-26-longitudinal-round.md) attempted all 33 inputs on one brain, with 32 replies and one preserved timeout. Meaningful recall and source-faithful recollection still fail in some cases. Access-age tier changes did not demonstrate the intended gist-first forgetting behavior. These remain release blockers, not validated human-memory equivalence.

The local embedding model embeds one memory per background job. After a large import, meaning-based recall covers new records only gradually: about 500 messages took twelve to thirteen minutes to store and embed on a four-core machine that was also running other benchmarks. Keyword recall works at once. For the same reason only 30 LongMemEval questions (each a history of about 500 messages) have been run.

MCP exposes tools; installing it alone does not automatically intercept a closed AI client's conversations. Streaming, general tool loops, multimodal input, native one-click installation, personality and emotion are outside this release. Windows and Linux desktop flows have not received real-machine acceptance. Human-inspired describes the design direction, not proven biological equivalence or infallible recall.
