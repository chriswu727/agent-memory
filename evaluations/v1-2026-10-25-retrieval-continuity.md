# Retrieval continuity repair and a failed answer diagnostic

The [stopped v5 campaign](v1-2026-10-25-longitudinal-v5-stopped.md) found an established duration preference missing from the host context. This batch repairs that omission and clarifies the citation verifier's attribution authority. A subsequent real host response still failed to carry the duration preference into its proposed schedule. The product remains below the longitudinal acceptance gate; local engineering checks and memory-use quality are separate results.

## Original failure and bounded repair

A read-only reconstruction restricted database table inputs to the exact pre-query source and memory versions before SQL ordering and limits. The old installed runtime reproduced both the original sixteen eligible recall items and the final ten selected memory blocks; its complete model context matched the actual host input byte-for-byte. There was no truncation at the intermediate 64k recall ceiling. The half-hour semantic preference and literal had zero lexical overlap and no association or episode route. Weak river/work matches gained additional association credit and displaced useful context at the final 16k ceiling.

The [retrieval change](../architecture/conversation-retrieval.md) retains relative lexical match strength, propagates a bounded strongest-seed score through one hop, and prevents self-boosting or seed rows consuming expansion capacity. A new bounded source-neighborhood route can retrieve short adjacent replies without inventing semantic relationships. It preserves source scope, exact evidence, hidden-record barriers and existing world/cutoff validation. Candidate truncation now reports partial scope separately from missing source data, avoiding a false read-fence failure when the current event tail is fully loaded.

Independent counterfactual reconstruction with the new runtime retained the exact same query and context ceiling. Both half-hour memories reached the final packet at positions five and six, with unchanged user source, revision, content hash and supporting span. The final packet contained fifteen memory blocks and used 15,920 of the 16,000 conservative context allowance, measured by the runtime's byte-based estimate rather than model tokenization. It still contained seven unrelated river/friend blocks. The result establishes recovery of this omitted preference, not generally sufficient semantic relevance.

## Real host response: failed

One explicitly bounded DeepSeek Pro host call used the new installed runtime's prepared context, the original host callback, original instructions and original user message. Only the memory context, request identity and corresponding input accounting changed. No new cue, future fact, learning, database publication or campaign continuation was introduced. The call used 5,975 input and 2,132 output tokens: **8,107 total**, with known usage and no retry.

The response proposed **30–45 minutes for planning and 60–75 minutes for drafting**, then asked whether to keep sessions closer to thirty minutes. It correctly retained Wednesday classes, free Tuesday/Thursday evenings and the one-off Friday visit. It did not carry forward the already supplied manageable half-hour duration as the default. That frozen diagnostic criterion failed. The user had expressed a preference, not an absolute prohibition; the failure is unnecessary re-teaching and weak continuity, not violation of an invented hard limit.

This proves that recovering the preference alone did not fix the answer in this observation. It does not establish a deterministic model cause. Applicability labels, distinction between user preferences and assistant proposals, task linkage and remaining irrelevant context need investigation before another longitudinal campaign. No answer-conditioned rerun or successful release claim follows from this result.

## Citation attribution contract

The new `citation-provenance-v1` contract permits only a selected citation's own bound speaker-role and delivery-status metadata to support recorded communication attribution. Uncited text, other proposals, inferred human identities and external completion remain unauthorized positive premises. Existing coverage, source, world and publication gates remain mandatory. Frozen `citation-coverage-v1` requests retain their original bytes. See the [contract](../architecture/citation-coverage.md) for the precise boundary.

Two predeclared real verifier observations completed with **36,292 known tokens** across two calls and no unknown usage. Both complete-excerpt attribution targets received supporting coverage, whole-proposal and individual-reference judgments. The omitted-letter-detail control received unknown coverage and an unknown whole-proposal judgment despite supporting individual references. The positive case changed only the citation scope and verification instructions; the negative case came from an older contract and also added the required coverage-verdict schema field. All proposals, references and source/context data were preserved.

An independent [installed-processor replay and publication-guard audit](v1-2026-10-25-citation-provenance-verification.json) reproduced the old request contents and matched the new verifier inputs to the actual calls. The processor accepted both attribution targets and rejected the incomplete target with `citation_coverage_unconfirmed`. Both results remained `partial`: the positive case's episode still failed fidelity, and the negative case retained an unrelated structural rejection. The in-memory publication guard rejected removal of a required coverage verdict and reinsertion of the incomplete target even when its whole-proposal verdict was changed to support. This checked the gate against the frozen source catalog, with no database publication or new model calls; it does not establish that all future verifier judgments will be correct.

## First candidate validation and local performance

The first full source suite recorded **1 failed, 5,140 passed and 4 skipped** in 474.20 seconds. The failing cross-conversation funding fixture required the whole historical obligation to fit into one funded request. Investigation confirmed a valid bounded partition with retained remainder, so the fixture was corrected to verify the funded subset, the original obligation and the public unassessed remainder separately. The two affected funding/continuous-learning files then passed **36 tests**. This preserves the original failed full-suite result; the focused correction is not presented as a successful full-suite rerun.

Other scoped checks on the first candidate passed: 33 source-neighborhood tests, 75 ranking/retrieval/source-route tests, and an overlapping 113-test candidate/cognition/read-fence group. The isolated installed-wheel checks passed one standalone chat flow and three desktop setup/upgrade/recovery flows. These groups overlap and are not added into an invented aggregate test count.

The [fixed local performance replay](v1-2026-10-25-retrieval-continuity-performance.json) used the installed `538809…` build and the preserved 10,000-record fixture after the first full suite exited. All **20/20** fixed labels were found; median latency was **86.232 ms**, p95 **100.953 ms**, and maximum **142.463 ms**, against the existing p95 threshold of 500 ms. All twenty observations were retained in their original order, with no discarded warmups or repeated measurement and zero model or embedding calls. This is an in-process `cue_recovery` diagnostic; it does not measure the new `continue_conversation` adjacency route, model response time or a production latency guarantee.
