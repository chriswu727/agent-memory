# Desktop installation and recovery validation (2026-10-24)

This validation covers local installation, stable brain identity, background service lifecycle, and integration configuration. It does not evaluate new long-term memory algorithms or model answer quality. The environment was macOS, Python 3.12, and local Docker. No paid model or GitHub CI was used.

## Delivered behavior

- `desktop setup` creates a stable private profile, configures the cognitive provider once, prepares dedicated PostgreSQL/pgvector, migrations, and a fixed brain, and starts the API and worker in the background. The cognitive model may initially be unconfigured; status reports this explicitly.
- Database operations, configuration updates, and instance lifecycle have separate locks. Repeated connections reuse the brain and service. Interrupted installation preserves a committed identity; missing or corrupt configuration does not silently create a new identity.
- MCP configuration contains only interpreter and profile paths. Connecting reads local credentials and automatically starts the service. Python `open_client()` also binds to the fixed brain without requiring copied tokens, URLs, or brain IDs.
- Readiness checks verify service identity, authentication, the actual database and brain, and the worker. Existing configuration does not imply a verified provider. MCP capability remains `tools_only`.
- Shutdown uses an authenticated instance-control endpoint rather than killing a PID. It waits for the worker to finish before stopping the database; on timeout, the database stays running. Default shutdown does not delete data volumes.
- Desktop processes do not search for a development repository's `.env`. Local HTTP ignores environment proxies. Docker is restricted to local endpoints, and the verified endpoint is pinned for Compose commands.
- Bounded lifecycle logs contain timestamps, fixed event codes, and instance IDs. They do not contain memory content or API keys.

## Validation

The real Docker end-to-end test is `tests/test_desktop_e2e.py`. It is skipped by default and runs only when `MEMORY_DESKTOP_E2E=1` is explicitly set. Each run creates an isolated test installation and database, then deletes only the volumes it created.

The test starts from a profile path containing Chinese characters and spaces, runs from an unrelated working directory, and deliberately inherits invalid database addresses, API keys, and HTTP proxies. It covers:

1. Cold startup completing migrations, API, worker, and initialization of exactly one brain.
2. Two concurrent connections reusing the same instance.
3. `BrainRuntime` input capture, deterministic generation, delivery, and completion through real HTTP and PostgreSQL, persisting two messages.
4. Service shutdown with data retained.
5. Automatic service restart through real MCP stdio using the generated configuration, which contains no secrets.
6. Stable brain and event IDs after restart; completed-turn recovery does not regenerate or redeliver.
7. Rejection of unauthenticated monitoring requests, with no test conversation or access key in lifecycle logs.

The test passed in the source environment, a standalone wheel installation, and an isolated tool environment installed from a local source ZIP with `uv tool install`. The ZIP used the same named-URL installation method as the README, with a local archive for validation, rather than relying on an editable source installation. Python files, the Compose template, every migration, and contracts in the wheel were compared byte for byte.

The first standalone-wheel run produced one pytest configuration warning: pytest-asyncio was absent from that test environment, but the project's `asyncio_mode` setting was read. The test itself passed. The final isolated tool environment included the test dependency and passed without that warning.

Regression testing found an intermittent composite unique-constraint violation during concurrent fixed-brain insertion. The original statement handled only `id` conflicts, although the table also had a `(tenant_id, owner_id, id)` unique constraint. It now handles all unique conflicts and still applies the original ownership check before returning the brain. A regression runs 20 rounds of 4 concurrent requests. Other tenants and other owners within the same tenant still cannot take over an existing brain.

The final full Python regression run reported **2,554 passed, 1 skipped** in 144.78 seconds. The sole default skip was the opt-in Docker end-to-end test above. It was separately run and passed in the isolated tool installation; the final concurrent cold-start version took 9.07 seconds. All 11 fixed-brain database tests passed separately, including the 20-round concurrency test. Ruff, diff checks, and sdist/wheel builds passed.

## Not yet covered

There is no native desktop installer yet; uv and working local Docker are still required. Windows path, ACL, and locking branches, and Linux paths, have implementations and unit tests, but neither system has completed end-to-end validation on a real machine.

No external agent configuration is edited automatically, and no specific host has a complete lifecycle adapter for messages, pre-inference context, delivery, and compaction. An MCP connection alone still cannot capture all chat. Provider credential validity, real semantic learning quality, and long-running load are outside this installation validation.

The local service identity handshake prevents sending access credentials directly to an unrelated service already occupying the port. It does not provide TLS or eliminate every race in which a malicious local process takes over the port after the handshake.
