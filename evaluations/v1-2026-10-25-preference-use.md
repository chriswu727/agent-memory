# Historical feedback use: verified implementation and bounded model observations

The final candidate clarifies how relevant historical feedback may guide a tentative suggestion without becoming a settled current fact. Its implementation checks pass. Three predeclared real host observations exercise the permission and its limits; whole-answer review still finds an unsupported present-state assertion and an overconfident negative heading. This is a repaired engineering checkpoint, not completed longitudinal acceptance.

## Change and compatibility

The [historical-suggestion boundary](../architecture/historical-suggestions.md) is shared by `memory-consumption-v4` and the optional `answer-grounding-v2` reviewer. Unknown applicability does not itself require the user to repeat relevant feedback before a reversible suggestion. Current user changes, false applicability, conflicts and retractions still constrain use. An assistant proposal does not become an adopted plan. Memory and applicability labels are unchanged.

New policy fingerprints prevent unfinished requests and already-bound reviews from silently acquiring the new authority. Already completed turns retain their replay behavior. The change adds no model request or rewrite loop to normal generation. The shared instruction boundary adds 1,103 UTF-8 bytes; it still consumes the existing input allowance rather than enlarging that allowance. The earlier [retrieval-only host diagnostic](v1-2026-10-25-retrieval-continuity.md) remains failed; recovering a memory did not by itself make the host use it.

## Real host diagnostic

The [independent record](v1-2026-10-25-preference-use-verification.json) preserves the frozen plan, request/response bindings, per-criterion findings and whole-answer limitations. Each case received exactly one response from DeepSeek Pro with high reasoning, at most 4,096 output tokens and a 240-second timeout. The total ceiling was three calls and 12,288 reserved output tokens. All three completed with **18,493 input + 5,484 output = 23,977 known tokens**, zero retries and no unknown usage.

The first case held the earlier failed prompt fixed except the generic interpretation protocol and request accounting. The other two were explicitly synthetic controls on the same memory packet, declared before execution. Criteria and previous answers were not added to the model requests. The packet remained 15,920 against the 16,000 conservative byte-based context allowance; whole-input estimates were 22,612, 22,745 and 22,604 against 24,000. These estimates are not provider-token measurements.

The narrow frozen criteria and supplemental defects remain separately recorded. They are not collapsed into an unqualified three-answer pass. Two responses also switch to Chinese despite English current inputs; this language drift was outside the six predeclared criteria and is retained as an additional quality issue. There was no database mutation, learning publication, automatic answer repair, repeated sampling or continuation of the closed v5 campaign. The optional answer reviewer was not enabled in these host-only observations; its deterministic policy and binding checks are separate evidence.
