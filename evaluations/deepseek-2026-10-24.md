# DeepSeek live memory pipeline evaluation: 2026-10-24

This evaluation used the account's available `deepseek-v4-pro` model with thinking enabled. Five of the final eight stages passed; three did not meet the predefined requirements. Model verification protocol problems were fixed, but gaps remained in context efficiency, the representation of unknown concepts, and proactive abstraction across experiences.

The [structured results and usage](deepseek-2026-10-24.json) preserve successes and failures from all three trial versions. All sources were fixed synthetic texts. Each scenario group used an isolated identity and brain; no content from existing user brains was sent. The trials exercised real `observe`, background learning jobs, publication, `recall`, and `prepare`, without manually inserting correct memories. Each stage allowed at most two model calls, for proposal and verification. No host chat model was called to generate an answer for scoring.

“Passed” means only that the fixed synthetic scenario met its predefined structure, provenance, temporal, and actual-output checks. Content phrases were auxiliary safeguards. The developer assistant also reviewed the claims and citations individually; there was no independent human annotation or long-term effectiveness review.

## Fixes prompted by the live trials

The initial exception relation omitted citations for the old belief. Verification also required each citation to establish the entire compound claim independently, so two complementary pieces of evidence were each judged insufficient. The fix requires relations to include exact citations for all endpoints and separates verification into support for each cited premise and a mandatory overall `proposal_verdict`. Both must pass: valid citations alone do not establish that the whole conclusion is correct. Source, world, time, exact-version, and complete semantic-span checks were not relaxed.

The second trial generated a correct claim and complete evidence, but the verifier omitted the optional `link_verdict`. The final protocol makes this field mandatory for every verification item: ordinary claims must use `null`; relations require an explicit verdict, and only `supports` permits publication. Regression tests cover omissions, unknown or opposing verdicts, and incorrect field use. After the fix, real exception and permanent-change proposals both passed generation and verification. The permanent-change recall budget failure remains recorded as a failure.

The usage meter initially could not parse compressed responses. Bounded gzip decoding and offline tests were added; completed calls were not repeated just to recover usage statistics.

## Context overhead diagnosis

After retaining the 48k-budget failure, an additional 64k database-read diagnostic used **zero model calls**. It retrieved all semantic endpoints at three time points and correctly represented the same-day exception, next-day restoration, and permanent replacement after the specified date. The larger budget was only a diagnostic; it did not turn the original result into a pass.

- The text of the three beliefs totaled 475 bytes; the rendered context was about 36.4KB, and the complete prepare response was about 122KB.
- Two relation certificates appeared six times across the three beliefs, accounting for about 10KB of duplication alone.
- The complete related semantic group required about 62.6k conservative estimation units, not tokens measured by the model's tokenizer.
- Historical source text could still enter `relevant_memory` without the current-applicability labels attached to semantic versions. No final-answer error from this was observed, but this entry path could not be considered consistent with current-rule handling.

The next priority should be compact context that presents each source and relation once, expands evidence through stable references when needed, and preserves complete related memory groups. Historical reports must also be distinguished from rules that can currently be applied. Simply increasing the budget does not meet the product goal.

Proactive abstraction also needs explicit consolidation objectives, candidate comparison, and output checks. Recording that a recollection occurred when given a recall cue does not establish autonomous generalization. Supplying the correct conclusion in the test would not substitute for that capability.

## Usage and validation

The three trial versions made **24 requests**, including 16 in the final version. Each explicitly capped output at 16,384 tokens, with no automatic retries. The 22 calls with confirmed usage totaled 122,209 input and 87,214 output tokens: 209,423 tokens. Usage for the first two calls is unknown because the meter did not yet support compressed responses; they cannot be counted as free or zero usage. These figures are not billing amounts.

The complete Python run had **1,302 passing tests**. A subsequent evaluation-oracle fix for valid explicit positive polarity was followed by **70 passing related oracle and recovery tests**, including two new polarity regressions. Ruff, build, and diff checks passed. No cloud CI or Codex/Claude subscription tests were run.

Raw diagnostics remain under the ignored `.local/` directory. The public JSON preserves synthetic inputs, published claims, relations, checks, output statuses, code fingerprints, safe usage data, and the free budget diagnostic summary. It contains no credentials, HTTP error bodies, or hidden reasoning. See the [README](../README.md#manual-deepseek-evaluation) for reproduction. Temporal checks injected a domain clock; they do not imply an existing host API for historical situations.
