# First-release foundations: 2026-10-25

This is an engineering acceptance record for the first hardening batch. It is not the first-release completion report and does not establish human-like long-term memory quality. Automatic feedback, supported installation recovery, and fresh real-model long-history acceptance remain subsequent gates in the [release plan](../architecture/v1-release-plan.md).

## Behavior exercised

The desktop identifies its loaded build from runtime, contract, and migration bytes. An independent two-build Docker test keeps the package version unchanged, detects an outdated daemon, migrates while retaining the original brain and sources, and rejects an older installation before it can stop the upgraded service. Schema checks reject unknown or non-prefix migration histories. Historical migration bytes are not authenticated by the legacy migration registry.

Feedback reinforcement now requires a unique exact delivered statement, the selected current memory revision, valid source closure, and preparation before delivery. Multiple preparations and unavailable preparation proof remain trace-only. Imported acknowledgements and unbound tool results do not reinforce memory. A normalized contribution ledger supports independently invalidating a corrected or erased feedback event, while surviving evidence retains its effect. Negative feedback cannot increase activation or refresh reinforcement time. Migration 014 resets unsupported legacy access aggregates; it retains original sources and assertions.

Learning progress separates processing coverage from retained semantic outcomes. An assessed rejection can advance coverage without counting as published memory. Missing or invalidated historical results remain unknown. The new communication-intent input contract separates citation permission from an actual request, while the independent verifier and output schemas remain unchanged. Frozen older input contracts preserve their payloads and instructions. Real-model classification accuracy has not been established by these deterministic tests.

Chat, recall, semantic, and answer-review adapters share bounded decompression, strict JSON/assistant-response validation, deadlines, redacted failures, and no transport retries. Provider usage has signed-64-bit bounds, must belong to a fresh per-thread call marker, and remains unknown when unsupported or invalid. Durable semantic operations settle proposal and verification independently. The authenticated cognitive-usage endpoint reports retained reservations, phase outcomes, known tokens, and unknown counts without response content. Its coverage excludes host generation, answer review, recall-controller calls, and account billing.

New cognitive snapshots reject automatic reclaim when a prior reservation was never settled. Crash tests interrupt after proposal and verification responses, reopen the database, expire leases, and attempt concurrent reclaim without another provider call. Reservations and uncertainty remain visible; explicit learning recovery creates a separately authorized child. Frozen legacy snapshots retain their earlier bounded-retry contract. A separately settled uncertain outcome may use previously authorized retry allowance, and a changed source can authorize fresh repair work without deleting older usage.
