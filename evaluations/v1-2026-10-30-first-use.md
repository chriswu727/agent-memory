# First use and live saved memory — 2026-10-30

This increment targets an existing agent user: install the plugin, confirm that messages arrive, try recall in a new session, and correct memory without restarting a conversation. It remains a pre-release; this work does not establish longitudinal answer accuracy.

## Implemented

- `membrain plugin setup` starts local memory and opens a single-use guided page, without asking for another model API key. The page distinguishes service readiness from received agent messages, supplies Claude Code/Codex connection instructions, and guides a cross-session preference check. User-written notes do not count as incoming agent messages.
- Local-model download failures remain visible and can be retried from the page. Downloaded files are not reported enabled before service activation. Keyword recall remains available during preparation. The retry endpoint requires the local credential.
- Saved-note and coming-up snapshots refresh before replies in ongoing sessions. Unchanged snapshots are not repeated; failed reads do not publish an empty replacement. Fingerprints are bound to the selected brain, and shared role-play context continues to exclude sensitive real-life notes. Removing a note cannot retract text the host has already received.
- A complete user-history block no longer skips a deliberate question about earlier assistant speech. English recommendation wording and Chinese references such as “你上次推荐” permit attributed assistant recall; references to another person's recommendations do not.
- Busy background work yields briefly between bounded per-brain slices. Idle and failed iterations retain their normal wait, and no deletion/publication checks are bypassed.

## Verification

An embedded PostgreSQL journey exercises setup with no cognition provider, an exact current-turn source reference, recording the completed turn, loading the preference in a new session, correcting it while that session remains open, and deleting it. Source links survive the correction. Separate checks cover snapshot-read failure, user/brain changes, sensitive shared notes, large plan lists, download failure and retry, endpoint authentication, and worker yielding.

The actual browser journey verified the initial no-message state, local-model preparation through the page, activation after restart, messages arriving from the Codex hook path, adding a preference from the first-use control, returning to the collapsed form/list, and switching connection instructions. Desktop and a 390-pixel mobile viewport had no horizontal overflow. Console inspection found no warnings or errors during the successful journey. This uses synthetic hook input, not a live subscription-backed Codex or Claude session.

The pinned local ONNX model was downloaded and used without a paid provider. A Chinese dietary question retrieved the earlier English sesame-allergy source among the first three results, with vector evidence. Two unrelated items ranked above it. This is a working-path smoke check and an explicit remaining relevance weakness, not an accuracy benchmark or proof that semantic ranking is solved. Earlier public benchmark scores were not rerun for this increment.

The stable focused suite passed 131 tests, retaining the existing multithreaded-fork warning. TypeScript passed 43 tests and strict type checking; Ruff, JavaScript syntax and package construction passed. A built wheel was installed in an isolated uv tool directory and its setup command started a separate embedded installation without a model provider. Final full-suite results and the final installer revision are recorded on the delivery pull request; a successful complete Verify run is required before merge.

An earlier local full attempt was invalidated: source changed during the run, and its auxiliary runner called pytest in-process from an unguarded script. A multiprocessing child reexecuted that script and failed its fresh-directory assertion. That interrupted run recorded 4,855 passes, four skips and three failures, including two service-start failures. An overlapping focused attempt also recorded a service-start failure. All logs are retained. With code fixed in place, no overlapping embedded test runs, and the normal pytest subprocess entry point, the affected tests passed in the 131-test isolated run. No product assertion was relaxed to turn those runs green.
