# First use and live saved memory — 2026-10-30

This increment targets an existing agent user: install the plugin, confirm that messages arrive, try recall in a new session, and correct memory without restarting a conversation. It remains a pre-release; this work does not establish longitudinal answer accuracy.

## Implemented

- `membrain plugin setup` starts local memory and opens a single-use guided page, without asking for another model API key. The page distinguishes service readiness from received agent messages, supplies Claude Code/Codex connection instructions, and guides a cross-session preference check. User-written notes do not count as incoming agent messages.
- Local-model download failures remain visible and can be retried from the page. Downloaded files are not reported enabled before service activation. Keyword recall remains available during preparation. The retry endpoint requires the local credential.
- Saved-note and coming-up snapshots refresh before replies in ongoing sessions. Unchanged snapshots are not repeated; failed reads do not publish an empty replacement. Fingerprints are bound to the selected brain, and shared role-play context continues to exclude sensitive real-life notes. Removing a note cannot retract text the host has already received.
- A complete user-history block no longer skips a deliberate question about earlier assistant speech. English recommendation wording and Chinese references such as “你上次推荐” permit attributed assistant recall; references to another person's recommendations do not.
- The original background-worker scheduling is retained after a shorter-wait experiment increased ingestion time without a meaningful catch-up gain in the measured fixture.

## Verification

An embedded PostgreSQL journey exercises setup with no cognition provider, an exact current-turn source reference, recording the completed turn, loading the preference in a new session, correcting it while that session remains open, and deleting it. Source links survive the correction. Separate checks cover snapshot-read failure, user/brain changes, sensitive shared notes, large plan lists, download failure and retry, and endpoint authentication.

The actual browser journey verified the initial no-message state, local-model preparation through the page, activation after restart, messages arriving from the Codex hook path, adding a preference from the first-use control, returning to the collapsed form/list, and switching connection instructions. Desktop and a 390-pixel mobile viewport had no horizontal overflow. Console inspection found no warnings or errors during the successful journey. This uses synthetic hook input, not a live subscription-backed Codex or Claude session.

The pinned local ONNX model was downloaded and used without a paid provider. A Chinese dietary question retrieved the earlier English sesame-allergy source among the first three results, with vector evidence. Two unrelated items ranked above it. This is a working-path smoke check and an explicit remaining relevance weakness, not an accuracy benchmark or proof that semantic ranking is solved. Earlier public benchmark scores were not rerun for this increment.

Before the scheduling reversion below, the stable focused suite passed 131 tests and the candidate full suite passed 5,963 tests with five skips, retaining the existing multithreaded-fork warning. TypeScript passed 43 tests and strict type checking; Ruff, JavaScript syntax and package construction passed. A candidate wheel was installed in an isolated uv tool directory and its setup command started a separate embedded installation without a model provider. Final full-suite results and the final installer revision are recorded on the delivery pull request; a successful complete Verify run is required before merge.

An earlier local full attempt was invalidated: source changed during the run, and its auxiliary runner called pytest in-process from an unguarded script. A multiprocessing child reexecuted that script and failed its fresh-directory assertion. That interrupted run recorded 4,855 passes, four skips and three failures, including two service-start failures. An overlapping focused attempt also recorded a service-start failure. All logs are retained. With code fixed in place, no overlapping embedded test runs, and the normal pytest subprocess entry point, the affected tests passed in the 131-test isolated run. No product assertion was relaxed to turn those runs green.

The candidate wheel was also upgraded to its exact pinned Git source, whose runtime build matched that candidate. Setup, capture, new-session notes and a live correction passed in that installed environment. Packaged defaults use a pinned GitHub source archive instead, removing the Git executable dependency. An isolated uv tool installation of the candidate archive and its setup command succeeded with an empty PATH and an explicit Python interpreter; Git was unavailable. The final archive installation is rechecked against the final runtime before merge. The source archive and wheel/Git installation paths are separate checks, not a PyPI release.

## Rejected scheduling experiment

The lexical fixture was run with 100 then 1,000 synthetic messages, without semantic processing. A separate control used the same candidate code with its busy-slice wait set back to one second in the test process. These are two sequential local installations, one observation each, not a production-capacity or statistical accuracy claim. [Raw measurements](v1-2026-10-30-first-use-performance.json) retain both conditions.

| Additional 900 messages / 1,000-message recall | 50 ms busy wait | 1 s control |
| --- | ---: | ---: |
| Ingestion | 29.96 s | 9.14 s |
| Ingestion plus all indexing settled | 75.52 s | 78.70 s |
| Warm recall median / p95 | 268 / 278 ms | 266 / 275 ms |
| Eight-client recall median / p95 | 2,107 / 2,132 ms | 2,147 / 2,195 ms |

The small catch-up difference does not justify the ingestion trade-off in this fixture. The shorter-wait change and its dedicated test were removed; the final runtime retains the original scheduler. No blanket performance improvement is claimed.

## Remaining product gates

- Verify the complete install/trust/record/recall/correct flow inside real supported hosts on each claimed platform.
- Evaluate new held-out longitudinal scenarios, changed preferences and assistant promises using actual host models; regression tests alone do not establish model compliance.
- Improve ingestion plus indexing catch-up and foreground latency under controlled load. The rejected worker change is evidence to preserve, not a capacity guarantee.
- Publish and verify an installable release across supported platforms. Git source pinning and wheel construction are not PyPI publication.
